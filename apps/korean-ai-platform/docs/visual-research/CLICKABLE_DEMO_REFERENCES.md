## Replit Agent

- **확인한 화면**: 메인 입력 화면, 에이전트 실행 화면
- **참고한 패턴**:
  1. 화면 중앙에 큰 자연어 입력창 배치 — "무엇을 만들까요?" 형태의 질문형 placeholder
  2. 입력창 아래에 템플릿/예시 카드를 가로 스크롤로 배치
- **복사하지 않을 요소**: 코드 에디터 통합, 실제 터미널, 파일 트리
- **Business 14 적용 방식**: 사용자 홈 상단에 질문형 제목 + textarea 배치. 템플릿은 그리드 카드로 표시.

## v0 (Vercel)

- **확인한 화면**: 메인 프롬프트 입력 화면, 생성 결과 화면
- **참고한 패턴**:
  1. 최소화된 UI — 입력창과 "Generate" 버튼만 첫 화면에 표시
  2. 생성 결과를 상단에 요약, 기술 상세는 하단에 배치
- **복사하지 않을 요소**: 코드 프리뷰, 실시간 렌더링, 다크 모드 기본
- **Business 14 적용 방식**: task detail 상단에 사용자 요약, 기술 정보는 disclosure로 접기.

## Manus

- **확인한 화면**: 태스크 생성 화면, 실행 진행 화면
- **참고한 패턴**:
  1. 태스크를 카드 목록으로 표시하고 상태별 색상 구분
  2. 실행 중 단계를 타임라인으로 시각화
- **복사하지 않을 요소**: 멀티 에이전트 오케스트레이션 UI, 실시간 브라우저 스트리밍
- **Business 14 적용 방식**: 최근 작업 카드에 상태 badge + 다음 행동 문구 표시. 기존 step timeline 유지.

## LangSmith

- **확인한 화면**: 트레이스 목록, 런 상세 화면
- **참고한 패턴**:
  1. 운영자 화면과 사용자 화면의 정보 밀도 차이 — 운영자는 테이블/메트릭 중심, 사용자는 요약 중심
  2. 기술 상세를 disclosure/탭으로 분리
- **복사하지 않을 요소**: 토큰 단위 비용 분해, 트레이스 트리, 평가 스코어
- **Business 14 적용 방식**: `/admin`은 기존 정보 밀도 유지, `/`는 사용자 중심 요약. 기술 정보는 disclosure 내부로 이동.

## 공통 적용 원칙

1. 첫 입력창이 가장 중요한 시각 요소
2. 템플릿/예시는 클릭 가능한 카드로 제공
3. 최근 작업은 상태 + 다음 행동 중심으로 표시
4. 기술 상세는 기본적으로 접혀 있고, 위험 정보는 항상 노출
5. 사용자 화면과 운영자 화면의 정보 밀도를 명확히 분리
