# #6063 모바일 시각 검수 실측 (2026-10-28, Chromium 140 / DPR 2)

## 1. 보고된 증상(390px 히어로 크롭)은 재현되지 않았다
실제 미리보기와 최신 main을 같은 조건으로 계측했다. 두 CSS는 바이트 단위로 동일하다(`static/styles.css` 27,115 B).

| 폭 | 문서 가로 오버플로 | 인물 박스 right | 얼굴 우측 여유 | 잘린 요소 |

| 260px | 0px | 240 | 66.5px | 0 |
| 280px | 0px | 260 | 66.5px | 0 |
| 300px | 0px | 280 | 66.5px | 0 |

| 390px | 0px | 370 | 69.7px | 0 |

240px까지 내려가도 얼굴 알파 경계(opaque bbox 기준)가 뷰포트 안에 있고 본문 텍스트와 겹치지 않는다. `object-fit: contain` + `max-width` 조합이 유지하는 상태이며, 이 규칙은 그대로 두었다.

## 2. 실제로 재현된 결함: 폰에서 내부 페이지의 내비가 전부 사라진다
`.top-nav`는 900px 이하에서 `display:none`이고, about·activity·policy·media 4개 페이지에는 다른 내비 링크가 없었다.

| 페이지 | 수정 전 가시 링크 | 수정 전 도달 불가 페이지 | 수정 후 가시 링크 | 수정 후 도달 불가 |
|---|---|---|---|---|
| index.html | 25 | 0 | 25 | 0 |
| about.html | 1 | 5 | 7 | 0 |
| activity.html | 1 | 5 | 7 | 0 |
| policy.html | 4 | 5 | 10 | 0 |
| media.html | 17 | 5 | 23 | 0 |

수정 전 about·activity의 "가시 링크 1건"은 화면 밖으로 세워둔 `.skip-link`(본문 건너뛰기)로, 페이지 이동 수단이 아니다.

수정 후 5개 페이지 × 6개 폭(320/375/390/430/768/1440) 전수 계측: **가로 오버플로 0px, 뷰포트 밖 요소 0건** (의도적으로 화면 밖으로 세워둔 `.skip-link` 제외).

## 3. 화면 증거 (동일 조건: 390×844, DPR 2, networkidle + 400ms)
- `before_about_390_footer.png` / `after_about_390_footer.png` — 의원 소개 페이지 하단. 수정 전에는 링크가 0건, 수정 후에는 index와 같은 바닥글 내비가 나타난다.
- `before_index_390_hero.png` / `after_index_390_hero.png` — 첫 화면 히어로. 두 이미지는 6px 간격 샘플링 기준 **차이 픽셀 0** (수정 전후 동일).
- 1440×1000 PC 첫 화면도 같은 방식으로 대조해 **차이 픽셀 0** (이미지 용량 절감 위해 파일은 남기지 않고 수치만 기록).

## 4. 터치 영역 관측 (수정 대상 아님, 보고만)
바닥글 링크 텍스트의 높이는 16에서 20px로 44px에 못 미친다. 이는 index.html 바닥글이 원래 가진 값이고 이번 수정은 같은 패턴을 재사용했다. 확대 여부는 디자인 판단이므로 CENTRAL 결정으로 남긴다.
