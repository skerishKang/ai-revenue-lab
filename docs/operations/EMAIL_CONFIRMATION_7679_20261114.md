# 공용 로그인 선택 확인 메일 (#7679, 2026-11-14)

이메일로 가입한 직후 "본인이 맞으면 눌러 주세요" 메일을 한 통 보낸다. 누르지 않아도 계정은 그대로 쓴다.
누르면 그 계정의 다음 로그인부터 서비스에 넘기는 프로필의 `email_verified` 가 참이 된다.

## 흐름

1. 이메일 가입이 끝나면 인증 서버가 Chat 의 서명 경로(`/internal/email-confirmation/send`)에 메일을 요청한다.
   가입 응답은 이 요청을 기다리지 않고, 요청이 실패해도 가입은 그대로 끝난다.
2. Chat 은 링크를 만들어 기존 메일 채널로 보내고 토큰의 해시만 답한다. Chat 에는 아무것도 저장하지 않는다.
3. 인증 서버는 그 해시와 만료 시각(7일)만 레지스트리에 둔다. 토큰 원문은 메일에만 있다.
4. 링크를 열면 확인 화면이 나오고, 버튼을 눌러야 확인된다(링크를 여는 것만으로는 확인되지 않는다).
5. 확인 기록은 계정을 연결할 때의 자격 증명에 묶이고, 계정을 지우면 같이 지워진다.

## 스위치

| 이름 | 읽는 곳 | 기본 |
|---|---|---|
| `PADIEM_AUTH_EMAIL_CONFIRMATION_ENABLED` | 인증 서버 Worker·DO, Chat | 꺼짐 |

비밀번호 찾기·복구 스위치와 서로 독립이다. 꺼져 있으면 메일 요청이 없고, 확인 화면 경로가 없고(404),
이전에 확인한 계정의 프로필도 `email_verified: false` 로 나간다.

## 켜기 전에 확인할 것

- **프로필을 받는 서비스의 정책.** `email_verified: true` 를 운영자 허용 목록 같은 판정에 쓰는 서비스가 있으면,
  메일 확인을 마친 이메일 가입 계정도 그 판정을 통과한다. 지금까지 이메일 가입 계정은 항상 `false` 였다.
  Chat 은 이 값을 권한 판정에 쓰지 않는다. 다른 서비스는 켜기 전에 확인한다.
- 메일 채널이 Chat 에 설정돼 있는지(`mail_channel_env.py` 의 이름. 값은 출력하지 않는다).

## 켜는 순서

1. Chat 과 인증 서버에 이 변경을 모두 배포한다. 스위치가 꺼져 있으면 동작이 바뀌지 않는다.
2. Chat 에서 먼저 켠다(경로가 생긴다). 그다음 인증 서버에서 켠다.
3. 시험 계정으로 가입 → 메일 → 버튼 → 다시 로그인해 프로필을 확인한다.

끄는 순서는 반대다.

## 보내는 양

- 같은 출처에서 한 시간에 3통, 서비스 전체로 하루 500통까지. 넘으면 메일만 건너뛰고 가입은 그대로 끝난다.
- 이미 확인한 계정, 지워졌거나 차단된 계정에는 보내지 않는다.

## 알려진 한계

- 다시 보내기 화면은 없다. 메일을 놓쳤거나 7일이 지나면 그 계정은 확인되지 않은 채로 남는다.
- 스위치를 켜기 전에 가입한 계정에는 메일이 가지 않는다.
- 이미 로그인해 있는 세션의 프로필은 다음 로그인 때 바뀐다.
