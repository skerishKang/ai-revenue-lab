# Chat 음성 서버 중계 설계 (2026-11-09, #6828 원칙)

원칙: 사용자 화면·응답·브라우저 네트워크 경로에 모델·프로바이더 이름·주소를 노출하지 않는다(PADIEM 등급만).
이 문서은 프로바이더 이름 대신 **"음성 프로바이더"** 로 쓴다. 코드 이동·기능 변경의 근거 문서.

## 1. 현재 경로와 노출 지점 (조사 실측)

| 구간 | 현재 | 노출 |
| --- | --- | --- |
| 실시간 전사(Live) | `static/voice-live-session.js` 가 브라우저에서 음성 프로바이더 `wss://…` 로 직접 WebSocket | **프로바이더 주소**가 정적 파일·브라우저 네트워크에 노출 |
| Live 인증 | 같은 출처 `POST /api/voice/live-token` → 단기 토큰.browser 가 `?access_token=` 로 WS URL 에 탑재 | **토큰**이 브라우저 네트워크 URL 에 노출 |
| Live 설정 | live-token 응답 `session.model` + 클라이언트 `models/` 접두사 | **모델 이름**이 응답·WS setup 에 노출 |
| 일반 전사 | 브라우저 → 같은 출처 `/api/voice/transcribe` → 서버 → private STT | 노출 없음(이미 중계) |
| TTS | 브라우저 로컬 `speechSynthesis` | 노출 없음(네트워크 없음) |

장기 프로바이더 키는 이미 private STT Worker 에만 존재(서버측). 노출은 "브라우저가 직접 여는 WS 주소 + 단기 토큰 + 모델 이름".

## 2. 목표 구조

- 브라우저는 **오직** `wss://chat.padiem.net/api/voice/relay`(같은 출처)만 안다. 정적 파일에 외부 wss/https 호스트·`access_token`·`models/` 를 남기지 않는다.
- 컴2 Chat 서버(중계)가 세션 인증 후 음성 프로바이더와 서버측 WebSocket 을 열고 프레임을 양방향 중계. 프로바이더 주소·키·모델은 서버에만 존재.
- 중계는 프로바이더 WS 주소를 **서버 설정(env)** 으로 주입(공개 코드에实名 없음). 미설정 시 4503 으로 닫고 사용자 문구는 PADIEM 등급만.

## 3. 앞단(Cloudflare front) WebSocket

- `padiem-chat-front` 는 순수 프록시로 WebSocket upgrade(101)를 그대로 통과시킨다(단위 시험 존재). 동일 출처 `/api/voice/relay` 는 front → 컴2 터널로 전달.
- **배포 조건**: 단계 1에서 front+컴2 터널을 실제로 통과하는지 확인되지 않으면 배포하지 않고 머지만 한다. (본 건은 사전 실측 미확인 → 머지 전용.)

## 4. 세션 인증·상한·재연결

- 로그인 사용자만: 기존 canonical session 재사용. 미인증 시 WS close 4401.
- 동시 연결 상한: 서버 카운터(기본 8). 초과 시 close 4429.
- 끊김·재연결: 클라이언트가 지수 백오프로 같은 출처 재연결. 서버는 세션별 토큰 회전(기존 live-token 수명) 재사용.

## 5. 지연·비용·사용량

- 지연: 브라우저→컴2→프로바이더 1홉 추가(터널 RTT 수십 ms). 오디오는 기존 PCM/Opus 프레임 그대로 중계(형식 변환 없음).
- 비용·사용량: 전사 경로와 동일한 등급 기준 비용 authority 로 기록(product_id/grade). 중계 연결당 사용량 카운터.

## 6. 실패 문구

- 모든 사용자 문구는 PADIEM 등급만. 예: "음성 연결이 원활하지 않아요. 잠시 후 다시 시도해 주세요." 프로바이더·모델 이름 금지.

## 7. 시험 계획

- 서버 중계 단위(가짜 프로바이더 커넥터): 인증·상한·양방향 프레임·종료.
- 비로그인 거부(4401/401).
- 가드: 정적 voice 파일에 외부 wss/https 호스트·`access_token`·`models/` 없음; live-token 응답이 토큰·모델을 브라우저에 반환하지 않음.
- 브라우저(가짜 프로바이더): 연결→말하기→응답 수신→끊기.
- 기존 시험 녹색, 기대값 하향 없음.
