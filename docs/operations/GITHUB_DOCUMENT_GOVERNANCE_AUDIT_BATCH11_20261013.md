## Core business vs technical distinctions

1. **Owner WEB-FIRST is a dated product-delivery priority, not a new common-platform business.** #3580 Hark Office owner correction explicitly prioritized browser-selected uploads and authorized Google Drive READ workbooks before Windows Resident Office fallback. This is distinct from the surrounding technical run-ID/ToolRuntime repairs and may need Owner priority reconciliation. Do not silently interpret Resident-first blocker as current UX policy or conflate B62 Chat with B66 Quote product.
2. **Five distinct Office authorization steps remain separate.** Source metadata selection ≠ canonical P01 LIST/READ approval ≠ first-party Engine verified one-use decision ≠ Windows Resident admitted execution ≠ resulting PDF/XLSX verified receipt. A synthetic approval or offline fixture, or the mere source presence of a UI button, never permits scanning the entire PC or accessing arbitrary customer files.
3. **Google Drive READ does not equal WRITE.** The Drive upload adapter needs exact independently authorized WRITE scope and binding, valid destination folder proof, immutable artifact material, one-use P01 CREATE approval, replay protection, and an active trusted Worker host. Historical #2010 READ-only binding and hermetic HTTPS tests alone leave live WRITE disabled. The Office two-file XLSX/PDF upload pair is **not atomic**; partial delivery requires explicit reconciliation, not uncontrolled retries.
4. **Telegram READ does not equal SEND.** Trusted bot secret source, paired destination, channel context, immutable owner-scoped artifact, SEND-specific grant, owner-confirmed action and actual provider receipt are separate. A source-only injected adapter, D1 reservation or fake-send test cannot prove live messaging or a general customer communications service.
5. **Execution, receipts and actual delivery differ.** ACK of a canonical Broker command does not establish both Office output bytes staged; staged binary does not establish a completed Drive upload; Engine confirmed workcopy intent does not itself read XLSX or render PDF; local SQLite/D1 hermetic tests do not establish Cloudflare production worker flags, live secret provision or migration application.
6. **Existing shared authority is sufficient.** IP-CORE P01 alone owns consent/Tool approval; Engine is trusted cross-runtime execution/receipt; IP-CONTROL owns identity/entitlement/provider connector grants; B62 owns owner-scoped browser interface; B54 owns Claw-local workflow, artifact/index and optional Windows/Office/Telegram/Drive adapters. No new general approval issuer, provider token store or duplicated shared platform should be inferred from these documents.
