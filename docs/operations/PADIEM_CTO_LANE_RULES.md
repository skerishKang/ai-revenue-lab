# PADIEM CTO·레인 운영 규칙

최종 갱신: 2026-11-01 (대표 지시로 작성). 모든 레인(아스트라·컴1 로컬·컴2·CGI)은 작업 전에 이 문서를 읽는다.

## 1. 대표 방침
- **출시 먼저, 실사용에서 나오면 고친다.** 극한 점검·과잉 검증·보안 훈계 금지(대표가 보안 전문가).
- 완료 = 실제 작업 1건이 처음부터 끝까지 성공. health·presence 같은 상태 신호만으로 완료라고 하지 않는다.
- 임의 상한은 제품 규칙이 아니다(10-28). 단 대표가 숫자를 정한 경우 그 숫자를 따른다(예: 웹 XLSX 1GiB).

## 2. 프롬프트 주는 규칙 (CTO)
- **조건부 프롬프트 금지.** "A가 끝난 뒤 B를 하라", "머지되면 하라" 같은 지시를 미리 주지 않는다.
  선행 작업 완료·머지를 **확인한 뒤에** 다음 프롬프트를 준다.
- 한 레인에 한 번에 하나. 쉬는 레인에는 겹치지 않는 일만.
- 같은 일을 두 레인에 주지 않는다. 레인이 맥락을 잃었으면 전체 프롬프트를 다시 준다.
- 최고 모델은 **막힌 일을 한 번에 끝낼 때만** 쓰고, 끝나면 다른 모델로 돌아간다.
- 대표에게는 기술 용어보다 "무슨 일인지 + 대표가 할 일"로 설명한다.

## 3. 레인 공통 규칙
- 레인은 **push만**. PR 생성·머지는 CTO.
- **배포·비밀 교체는 CTO가 프롬프트로 지시한 경우 레인이 수행한다.** 지시 없는 배포는 하지 않는다.
- 머지는 컴1의 `automerge.py`(CI 감시 후 squash 머지)로 한다. GitHub auto-merge 기능은 쓰지 않는다(`auto_merge=null`이 정상).
- 비밀 값은 출력·argv·repo 금지. stdin 또는 파일→파일로만. 비밀번호 입력 금지.
- Cloudflare 배포는 `--keep-vars`. wrangler는 `npx -y wrangler@4.156.0`.
- 보고는 "됨/안 됨 + 커밋 해시 한 줄". push했다고 보고하기 전에 `git ls-remote`로 원격 SHA를 확인한다(로컬 커밋만 있고 push 안 된 사례 있음).
- 기존에 main에서도 실패하던 시험은 "기존 실패"로 표시하고, 내 변경과 섞지 않는다.

## 4. 컴2 = 운영 단일 레인 (병목)
- Chat(8798)·P01(8811)·B14(8789)·큐(8797)가 모두 컴2. `.env` 수정·재시작은 **한 레인만, 한 번에 하나씩**.
- 컴2 재시작이 필요 없는 준비(마이그레이션 복사본 점검, Cloudflare 쪽 키 등록, 코드 수정)는 아스트라에 나눠 컴2 대기열을 줄인다.
- 배포 후 확인은 **로그인 후 AI 답변 1회**까지(10-31 컷오버 때 health·손님 화면만 보고 AI 503을 놓친 교훈). `deploy_from_main.sh --ai-check`.
- `deploy_from_main.sh`는 수정 PR이 머지되기 전에는 쓰지 않고, P01은 `deploy/host-com2/p01/install.sh --apply`로 직접 설치.

## 5. 구조 요약
- `chat.padiem.net` → Cloudflare 앞단 `padiem-chat-front`(문지기: 엣지 HMAC, 정적 폴백) → 컴2 Chat. 앞단은 /health·연결 실패·타임아웃만 장애로 판정(#6485).
- 롤백용 Cloudflare Chat Worker 보관. D1은 컷오버 이후 갱신 안 됨(역방향 복사 도구 보류).
- 로그인: padiem-auth(auth.padiem.net) 공통 로그인 + 컴2 Chat 자체 Google 로그인(hybrid).
- 성경앱(B61 StoryMemory): 정식 주소 `storymemory-padiem.pages.dev`. 소스 `apps/storymemory/`. 배포는 `--project-name storymemory-padiem` 명시(-567 프로젝트는 미사용). Pages Preview 환경에는 입구 비밀이 없다.
- 마이그레이션 번호: 080 = #6445(문서 소유자, backfill 동반), 다음은 081.
