# #5728 SNS 사진 구성 UI 증거 (2026-10-25, CGI-UI LOCAL)

before = 운영(#5727 배포 상태), after = 본 PR 로컬. 1440×900, 동일 자동화 흐름.

## before (운영)
- 사진 URL 텍스트 필드 존재(records.json url_field_present=true), 사진 선택기 없음.

## after (본 PR)
- 사진 URL 필드 제거 → `사진 추가` 다중 선택(image/*) + 썸네일 목록 + ↑↓ 순서 + 삭제 + 블로그 `삽입 위치`(자동/맨 앞/N문단 뒤/문단 끝).
- 사진 2장 실제 추가: harbor-1/2.png 목록·"2장" 카운트.
- 생성: 프롬프트에 `첨부 사진: N장 (파일명…)` 로스터(사진 URL 라인 소멸) + 플랫폼별 지시(블로그=문단 사이 삽입 안내 / FB·IG=본문 이미지 설명 금지).
- 미리보기: 블로그 = 문단과 사진 교차(after records: P/IMG/IMG 시퀀스), 페이스북·인스타 = 본문 아래 별도 미디어 그리드 + "자동 게시 아님" 고지.
- 플랫폼 전환: 본문 텍스트·사진 2장 유지 + 그리드 전환 확인.
- 저장·복사·다운로드: 기존 경로 유지(텍스트 초안). 사진은 세션 구성용(보관 아님 — 백엔드 인계 노트 참조).

## 백엔드 인계 (필요 API 변경 — 본 PR 미구현, #5728 이슈에 기록)
이미지의 프로젝트 파일 보관을 위해서는 `BINARY_PROJECT_FILE_MEDIA`(현재 PDF/DOCX만)에 image/png·jpeg·webp 추가 + 이미지 비파서 저장 분기 필요. 계정 격리·기존 라우트 재사용 전제.
