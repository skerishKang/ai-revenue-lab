## 현재 확인과 선행 과제

- 컴2 Chat 및 broker는 설치되지 않았다. 설치와 실제 전환은 승인된 창에 수행한다.
- Worker의 동결은 컴2 전용 센티널과 다르다. 현재 센티널은 Cloudflare Worker 쓰기나 이미 수행 중인 작업을 멈추지 않는다.
- Worker의 HTTP 및 백그라운드 쓰기를 중단하고 진행 중인 쓰기 종료를 확인하는 방법이 필요하다. 완료를 증명할 수 없으면 최종 export를 시작하지 않는다.
- 현재 역방향 export는 SQLite 사본만 생성한다. D1 적재 및 일치 검증은 준비되지 않았다. 되돌리기 도구가 검증되기 전 전환하지 않는다.
- D1, broker/queue 소유 표 및 R2 객체는 각 정본을 구분한다. PC 대기열 전환은 이 계획 범위가 아니다.
- 예약 백업의 SQLite와 SQL 복원 검사는 통과했고 마이그레이션 장부는 076이다. 최신 main의 migration 파일과 비교하고 대상 스키마를 맞춘 뒤 실제 export에 plan/load/verify를 실행한다.

## 준비

Qoder는 승인 후 Chat과 broker를 각각 설치하고 설정 이름과 파일 존재·권한을 검증한다. 비밀 값은 보고하지 않는다. loopback health, 승인된 터널 및 인증 의존성을 확인한다. 077·078 포함 최신 migration 상태와 데이터·R2 접근을 점검한다. 파일 업로드·견적서·로그인·대화 목록을 리허설한다.

## 전환 순서 — 실행 보류

1. 대표가 시간 창을 정하고 Qoder가 준비 상태를 확인한다.
2. Worker HTTP 및 백그라운드 쓰기 동결 → 진행 중 쓰기 종료 확인 → 컴2 쓰기 센티널 활성화.
3. 최종 D1 export를 안전한 위치에 보관 → 동일 스키마의 컴2 SQLite에 plan/load → 원본 포함 표별 행 수와 해시 verify. 차이나 실패가 있으면 앞단을 전환하지 않는다.
4. 승인된 앞단 구성과 Custom Domain 전환, COM2_CANONICAL=writes 확인. 쓰기 재개 후 로그인·대화 목록·프로젝트 파일·견적서 및 일반 채팅 스모크.
5. 30분 관찰: 1101/1102 0건, 5xx와 응답 시간은 전환 전 동등 경로 기준과 비교해 CTO가 판정한다. 요청 수가 없거나 측정값이 없으면 UNKNOWN이다.

점검 예상 시간은 실제 export·적재·대조·전환 리허설을 측정하기 전 UNKNOWN이다. 대표에게 분 단위를 확정해 안내하지 않는다.

## 되돌리기 — 도구 준비 전 실행 금지

컴2가 정본인 동안 쓰기가 발생했다면 두 쪽 쓰기를 동결하고 진행 중 작업이 끝났는지 확인한다. 컴2에서 사본을 생성해 D1 복원 게이트에 제출하기 전 스키마·소유 표·데이터 일치 검사와 무변경 실패를 검증한다. 적재 후 D1 행 수·해시 일치를 확인한 다음 도메인을 Worker로 복귀하고 쓰기를 재개한다. 현행 일반 D1 migration 게이트는 데이터 핸드백을 제공하지 않으므로 별도 구현·검증이 필요하다. 도메인만 먼저 옮기면 컴2에 쓴 데이터가 누락될 수 있다.
