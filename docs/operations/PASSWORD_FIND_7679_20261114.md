# 공용 로그인 비밀번호 찾기 (#7679, 2026-11-14)

로그인 화면의 "비밀번호 찾기"는 #7652(#7606)의 "메일 링크로 본인 확인" 장치를 그대로 쓴다.
새로 만든 저장소·마이그레이션·비밀은 없다.

## 무엇을 하나

1. 로그인·가입 화면의 "비밀번호 찾기" → 이메일 입력.
2. 응답은 누구에게나 같은 화면(202)이다. 대상인지, 메일이 나갔는지, 횟수 제한에 걸렸는지와 무관하다.
   응답을 먼저 내보낸 뒤에 조회와 메일 발송을 한다.
3. 대상이면 15분·1회용 링크가 메일로 간다. 링크의 토큰은 메일에만 있고 서버에는 해시만 남는다.
4. 링크에서 새 비밀번호를 정하면 그 계정의 로그인 세션과 갱신 토큰이 끊기고 비밀번호가 바뀐다.

## 대상

| 상태 | 처리 |
|---|---|
| 이메일로 가입했고 공용 로그인으로 들어온 적이 있는 살아 있는 계정 | 비밀번호 바꾸기 (이 문서) |
| Chat 만 탈퇴해 자격 증명이 지워졌고 다른 서비스가 계정을 쓰고 있음 | 복구 (#7652, 그대로) |
| Google 로만 가입한 계정, 탈퇴한 계정, 차단된 계정, 없는 주소 | 대상 아님. 응답은 같다 |
| 계정을 연결한 뒤 자격 증명이 다시 만들어진 주소 (#7551) | 대상 아님. 응답은 같다 |

판정은 한 곳에서 한다: 인증 서버 `AuthStateObject.emailRecoveryCandidate` (mode `restore` / `reset`).
Chat 은 그 판정을 받은 요청만 같은 토큰 장부(마이그레이션 114)에 기록한다.

## 스위치

| 이름 | 읽는 곳 | 기본 |
|---|---|---|
| `PADIEM_AUTH_EMAIL_RECOVERY_ENABLED` (#7652) | 인증 서버 Worker·DO, Chat | 꺼짐 |
| `PADIEM_AUTH_PASSWORD_FIND_ENABLED` (#7679) | 인증 서버 Worker·DO, Chat | 꺼짐 |

`PASSWORD_FIND` 는 `EMAIL_RECOVERY` 가 켜져 있을 때만 동작한다. 꺼져 있으면 화면·응답·Chat 호출이
#7652 그대로다(`apps/padiem-auth/test/password-find-off-baseline.json`).

## 켜는 순서

1. 메일 채널이 Chat 에 설정돼 있는지 확인한다(`mail_channel_env.py` 의 이름. 값은 출력하지 않는다).
2. Chat 과 인증 서버에 이 변경이 모두 배포돼 있어야 한다. 순서는 상관없다. 한쪽만 새 코드여도
   스위치가 꺼져 있으면 동작이 바뀌지 않는다.
3. `PADIEM_AUTH_EMAIL_RECOVERY_ENABLED=true` 를 Chat → 인증 서버 순서로 켠다(#7652 의 순서).
4. `PADIEM_AUTH_PASSWORD_FIND_ENABLED=true` 를 Chat → 인증 서버 순서로 켠다. Chat 이 먼저여야
   인증 서버가 보낸 요청을 Chat 이 받는다. 반대 순서면 그 사이의 요청은 메일 없이 같은 응답으로 끝난다.
5. 시험 계정으로 요청 → 메일 → 새 비밀번호 → 새 비밀번호로 로그인, 이전 기기에서 다시 로그인 요구를 확인한다.

끄는 순서는 반대다(인증 서버 → Chat). 끄면 이미 나간 링크도 쓸 수 없다.

## 알려진 한계

- 이미 발급된 접근 토큰은 최대 15분 동안 유효하다(#7652 와 같다). Chat 은 자기 세션을 바로 끊는다.
- 공용 로그인으로 한 번도 들어온 적 없는 Chat 직접 가입 계정은 대상이 아니다.
- 요청 횟수 제한은 #7652 의 장부를 같이 쓴다: 주소별·출처별 60초 간격, 하루 5회, 전체 하루 1,000회.
