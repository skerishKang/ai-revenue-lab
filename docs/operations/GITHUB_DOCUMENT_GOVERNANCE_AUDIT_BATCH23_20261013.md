## Technical and business governance distinctions

1. **Contact-verification technology versus actual customer onboarding.** The central Control Plane can manage short-lived OTP challenges and reusable contact-verification receipts while DanjiOn holds its own customer contact PII, apartment rules and account database. The repository sends through a network-free transport simulator; it does not establish live Kakao/SMS provider permission, legally certified identity or consent for cross-product account data sharing.
2. **B64 earning opportunities/rewards need separate Owner contracts.** An empty-supply Cloudflare Worker and immutable opportunity-version schema do not activate Korean reward partners, ad inventory, wallet/payout custody, customer payments or marketing rights. Only after external partner evidence and owner approval may a live reward inventory be described.
3. **B66 document intake and administrator claims remain fail closed.** The server file adapter source rejects actual Pages intake/failed model-route; QuoteCore retains price arithmetic authority. The separate admin UI proposal must verify administrator identity and member entitlements server-side, avoid accessing stored private quotation content and label shared Chat quota counters accurately rather than falsely calling them B66 model usage.
4. **Software supply-chain provenance is independent of runtime adoption.** Pillow source audit, platform native wheel provenance and later exact wheel receipt are sequential evidence, not interchangeable. Old source-only Draft/HOLD should not override later scoped receipts, yet no unreviewed wheel, arbitrary codec process, skill registry or production image pipeline is permitted. Pinned pypdf optional external decoders require separate trust and binary controls.
5. **Agnes candidate records have been retired.** Its old local test and shared free-pool constraints are historical; provider-specific terms, current free/paid eligibility and B14 catalog approval remain separate. Do not copy environment keys or infer today's model roster from the retired directory index.
6. **Desktop Shell is not Claw's executor.** The bounded Electron renderer/main interface projects progress and approvals; P01, device broker/pairing, true local-run authority, actual signed installer publication and withdrawal remain separately gated. Adapted third-party ZCode Apache-2.0 license and attribution must be retained for applicable package distribution.
7. **Living Learning, B60 API discovery and Sidecar are different services.** Living Learning's Firebase sign-in cannot silently grant paid lessons, product-role membership, or real customer Neon/Modal activation. B60's cinematic AI API explorer uses locally saved watchlists and historical official-source entries, not a continuously live verified free-tier feed. Reusing cross-project LoveTree assets requires owner/editorial rights review. IP-SIDECAR only displays sanitized state, never operates models or authorizes customer action.
8. **CI and documentation history are not commercial rulebooks.** Ephemeral CI runner proposal was never provisioned; do not expose a credentialed computer to public PR builds. Browser cache and workflow de-duplication preserve source/security gates. September documentation ownership reconciliation and technical diagram snapshots are dated, not modern company business authority or present-day Product readiness.
