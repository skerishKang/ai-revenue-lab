## 1. CTO 결정

**작은 UI/UX 작업의 테스트 목적은 테스트 건수 채우기가 아니라, 사용자가 요구한 정확한 화면 결과를 가장 짧은 경로로 증명하는 것이다.**

기본 실행 경로:

```text
요구 1~3개 확인 → 로컬에서 변경 → 기존 Tabbit 창/세션으로 해당 제품 열기
→ 요구한 클릭·입력·리사이즈만 수행 → 1장(필요하면 2~3장) 캡처
→ 직접 관련된 확인 PASS → 기존 필수 CI/배포 게이트 → 라이브에서 1회만 확인
→ 간단히 보고
```

- **브라우저 1순위: Tabbit.** 승인된 원격 Windows 호스트에서 `%LOCALAPPDATA%\Tabbit\LocalAgent\bin\tabbit-cli.exe` 설치를 확인함. 기존 승인된 탭/로그인 상태를 재사용할 수 있을 때 사용한다. 직접 화면을 보지 않았으면 **직접 봤다고 주장하지 않는다**. 접근/세션이 없으면 대기 또는 대체 브라우저를 명시한다.
- UI 진단/스크린샷은 대개 **1장**, 상이한 상태(예: 넓은 창/좁은 창)로 확인이 필요한 경우 최대 **2~3장**. 사용자가 그 이상을 명시하거나 실제 시각 결함이 추가로 발견된 경우에만 확대한다.
- **기존 로컬 서버/기존 Tabbit 연결 우선.** 브라우저 재설치, 자동화 환경 신규 구축, 가짜 테스트 계정 반복 생성, 장시간 백그라운드 서버 초기화는 기본 경로가 아니다.
- 한 화면의 문구·마진·너비를 바꿨다고 66개 테스트 파일/다중 매트릭스를 직접 반복 실행하지 않는다. UI QuickCheck를 위해 매번 새 Playwright 테스트 모듈을 만들지 않는다.
- 목표: **Tabbit의 준비된 세션에서 검증 자체 30–90초**. 개발·GitHub 필수 CI·운영 배포 대기시간은 별도로 기록하며 90초 완료를 보장하지 않는다.

## 2. 소규모 작업의 테스트 선택

| 수정/검증 주장 | 기본 증거 |
|---|---|
| 중앙 정렬·크기·색·간격·반응형 | 실제 Tabbit 화면 1~2장; 필요한 창 너비의 시각 확인; 가로 스크롤 여부 |
| 클릭·모달·입력·인사 응답 | 해당 실제 액션 후 Tabbit 화면 1장 |
| 기존 초안/계정 데이터가 삭제되지 않았다 | **스크린샷만으로 충분하지 않음**. 변경 경로를 좁게 확인하는 저장 상태/비변경 assertion 1개와 액션 화면 |
| 모델 라우팅·B14 호출·P01·권한·저장·WRITE·계산·PDF 출력 변경 | **UI QuickCheck 단독 불가**. 영향받는 계약·보안·저장 및 실행 검증을 기존 정책 T2/T3에 따라 추가 |
| 여러 화면에 걸친 전면 디자인 교체 | QuickCheck 불가. 기존 UI 방향·앵커·표면 수용 정책 적용 |

**기준:** 변경 코드가 실제로 건드린 동작의 근거만 검증한다. 설정된 **필수 GitHub CI, 브랜치 보호, 보안 게이트, 승인 및 정규 배포 절차를 우회하지 않는다.** 자동 실행된 무관한 검사는 관련성 기준으로 분류하되 플랫폼이 강제하는 상태는 준수한다.

## 3. 예: 사용자가 요청한 B66 두 가지 변경

| 요청 | Tabbit 직접 확인 | 증거 |
|---|---|---|
| 첫 화면에서 `하이` 입력 시 덮어쓰기 경고 금지 | `하이` 입력 → 정상 인사 응답/경고 없음 | **스크린샷 1장**. 저장 데이터 비변경 주장에는 별도 작은 assertion 1개 |
| 창을 줄이면 `편하게 시작하세요`와 입력창 가운데 | 실제 창을 **한 번** 좁힘 → 중앙 정렬/가로 스크롤 없음 | **스크린샷 1장** |

- 여기에는 8개 뷰포트, 66개 기존 테스트 파일, 4번의 같은 검증 반복이 **필요하지 않았다**.
- 기술적 이유가 있으면 추가 검증을 허용하되, **무엇을 보호하기 위해 필요한지** 먼저 명시해야 한다.

## 4. Tabbit 사용 및 증거 규격

- **먼저 URL 확인:** 사용자가 본 도메인, 실제 실행 환경, 변경 적용 리비전을 확인. 잘못된 스테이징 화면을 운영 검증으로 보고하지 않는다.
- Tabbit CLI와 연결된 브라우저/탭을 통해 탐색·클릭·입력·창 조절·화면 캡처를 수행한다. CLI 명령과 지원 기능은 실제 설치 버전의 도움말/스킬을 확인하고 호출한다. 이용 불가라면 추측한 명령을 계속 시도하지 않는다.
- 기존 탭/프로필은 사용자 승인 범위 내에서만 사용한다. **로그인 비밀번호·쿠키·토큰을 내보내거나 관리자 승인/P01 버튼을 대리 우회하지 않는다.** 다른 실제 고객 견적을 수정하지 않는다.
- 1~3개 결과 이미지에 **제품/URL, 리비전, 창 너비, 수행 액션, 결과, 캡처 시각**을 연결한다. 계정 정보/견적 민감내용이 보이면 공개 증거에서 가리거나 링크 권한을 제한한다.
- 실패 시는 실패 화면 1장과 1줄의 재현 단계만 기록. 더 많은 테스트를 시작하기 전에 원인을 수정한다.

## 5. CTO 최종 5줄 보고

```text
CHANGES=요청한 변경 1~3건
TABBIT_UI_CHECK=PASS|FAIL|BLOCKED (실제 본 URL / 너비)
SCREENSHOTS=1|2|3 (증거 경로/링크)
RELEVANT_TESTS=0|1|N (UI 밖으로 영향이 있으면 이유)
REQUIRED_CI_AND_DEPLOY=PASS|BLOCKED|PENDING, ELAPSED=...초
```

**운영 규율:** UI 화면 2개를 고치기 위해 별도 증거 패킷 10개와 반복 테스트를 만드는 것은 금지. 다만 잘못된 견적 삭제·권한 상승·과금·파일 변경을 **스크린샷 한 장만으로 안전하다고 단정하는 것 역시 금지**.

이 문서를 읽었다는 이유만으로 자동화 CLI를 구현했다고 주장하지 않는다. 재사용 가능한 최소 스크립트/프로필이 필요하면 #4458에서 짧게 구현하되, 현재 UI 작업의 병목으로 만들지 않는다.
