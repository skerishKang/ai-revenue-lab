# B14 모델 선정·평가 운영 기준 (2026-10-09)

> **현재 작업 기준 문서.** 모델 등록의 유일한 실행 원본은 `apps/korean-ai-platform/app/pilot/b14_models.json`, 승인 권한은 [Owner 모델 정책](MODEL_CHANGE_OWNER_APPROVAL_POLICY.md), 과거 결정 내역은 [Owner 결정 장부](B14_OWNER_MODEL_DECISION_LEDGER_2026-10-08.md)이다. 본 문서는 **평가 방법과 실측 결과**를 정리한다. 날짜가 붙은 결과를 영구적인 모델 성능 순위로 사용하지 않는다.

## 1. 선정 원칙 — 먼저 성능을 측정하고 사용자에게 선택권을 준다

1. **사용자가 실행할 모델을 직접 선택한다.** 제품에서 보이는 기본 선택값을 제공할 수는 있지만 사용자가 변경할 수 있어야 한다. 모델을 자동 전환하거나 실패를 다른 모델로 몰래 대체하지 않는다.
2. **등록과 합격은 다르다.** 등록됨, API 응답 가능, 견적 추출 정확, 제품 PDF 완성, 고객용 출시를 별도 상태로 판정한다.
3. **현재 9개를 먼저 평가한다.** 부족하면 Owner가 준비한 추가 후보를 같은 기준으로 시험한다. StepFun Step 5는 중요 후보이지만 현재 9개 등록 모델에는 속하지 않는다.
4. **모델은 견적서를 그리지 않는다.** B66에서 모델은 품목·수량·단가·거래처 등의 사실을 추출한다. 금액 계산은 QuoteCore, 레이아웃·PDF 생성은 승인된 렌더러의 책임이다.
5. **한 번에 한 모델의 사양·요청 매핑·실측을 검증한다.** 검증된 절차를 나머지 모델에 재사용한다. 근거 없는 공통 최대값이나 공통 리즈닝 옵션을 전 모델에 적용하지 않는다.
6. **보고는 질문·실험 범위에 집중한다.** 관계없는 보안·개인정보·윤리 강의, 과장된 경고, 방어적 단서 문구를 모델 평가 보고서에 붙이지 않는다. 테스트 성공/실패, 설정값, 원인과 다음 조치만 보고한다.

## 2. 한 모델에 대해 확인할 4가지 제한

| 구분 | 무엇을 확인하는가 | 판정 근거 |
|---|---|---|
| **모델 능력** | 입력 컨텍스트, 이론적 최대 출력, 텍스트·이미지 입력, 리즈닝 수준, 리즈닝 기본값 | 해당 제공자의 **현재 공식 모델 문서** |
| **B14 소프트웨어** | 최대 요청값, 입력 메시지 제한, 필드 검증, 전송 파라미터, 타임아웃, 응답 파싱 | 최신 `main` 실행 코드와 회귀 테스트 |
| **실제 프로젝트 할당량** | 무료/유료 등급, 활성 RPM(분당 요청), TPM(분당 입력 토큰), RPD(일일 요청), 공유 프로젝트 범위, 사용량 | **실제 제공자 대시보드의 해당 프로젝트**와 필요 시 제한적 실측 |
| **B66 제품 예산** | 견적 한 건의 실제 입력 길이, 출력에 필요한 토큰, 허용 지연, 최종 QuoteDraft/PDF 정확성 | 동일 합성 견적 시험과 B66 E2E |

**모델 최대 출력 ≠ B14 요청 허용값 ≠ 무료 프로젝트의 RPM/TPM/RPD ≠ 제품별 출력 예산.** 하나의 값을 나머지 값처럼 사용하지 않는다.

한도 수치는 출처와 확인 날짜를 붙인다. 계정별 값이 확인되지 않았으면 **미확인**으로 기록하고 임의의 무료 티어 숫자를 만들지 않는다. 429는 요청·토큰·일일 한도 등 이용 가능성 문제이며, 추출 능력 0점으로 처리하지 않는다. 504도 동일하게 분리한다.

## 3. 현재 9개 등록 모델의 견적 추출 평가 — 2026-10-09

동일한 합성 한국어 QKR 시험 세 건(기본 견적, 단가 미정, 12개 품목)을 9개 모두에 적용했다. 유망한 두 모델에는 나머지 일곱 건을 추가했다. **총 41개 실제 B14 경유 요청**이며 클라이언트 자동 재시도·대체 모델 호출은 없었다.

| `google/gemini-3.1-flash-lite` | **7/10** | 10/10 | 프로젝트명/미정 단가·0원 필드 오류, 한 건 실행 메타데이터 불일치 |

- **표본 수가 다르므로** 10건 완료 모델의 7/10과 3건 시험 모델의 2/3을 동등한 최종 순위로 취급하지 않는다.
- **HTTP 200만으로 합격 판정하지 않는다.** 필드 정확성, JSON 구조, 선택한 exact 모델 ID/제공자/실제 응답 경로, 반복 시 안정성을 확인한다.

- B14의 한 품목 실제 PDF 미리보기·출력 비교는 통과했으나, 12개 품목에서는 2페이지로 넘어간 내용이 관측됐다. 이는 **모델 채점과 별개의 렌더링 과제**이며, 고객용 완성 검증이 아니다.

- 모델: `stepfun/step-5-preview-free` (Kilo 경유 추가 후보), [Draft #3835](https://github.com/skerishKang/ai-revenue-lab/pull/3835).

- 다음 시험: Owner가 지정한 ZCode 모델·제공자 설정 그대로 B14를 경유하지 않고, 제한된 로컬 단일 호출부터 확인한다. 429 여부를 구분한 뒤 같은 QKR 견적 시험을 수행한다. 등록·운영 변경은 별도 판단한다.

## 5. 첫 모델 설정 파일럿: Gemini 3.1 Flash-Lite

| 항목 | 현재 확인값 |
|---|---|
| B14 ID | `google/gemini-3.1-flash-lite` |
| 모델 입력 컨텍스트 | 1,048,576토큰 |
| 모델 이론적 최대 출력 | 65,536토큰 |
| 공식 리즈닝 단계 | `minimal / low / medium / high` |
| 기본 리즈닝 | `minimal` |
| 현행 B14 명시적 `max_tokens` | 1–4,096 허용, 4,097 이상 거부 |
| `max_tokens` 생략 | 제공자 기본 동작에 위임 |
| 현행 B14 문자 제한 | 단일 텍스트 메시지 32,000자 |
| Google 프로젝트 무료/유료 등급 | **미확인** |

- 모델의 **65,536토큰 출력 능력을 곧바로 제품 요청 기본값이나 무료 할당량으로 설정하지 않는다.**
- OpenAI 호환 Google API가 지원하는 리즈닝 필드라도 현재 B14가 직접 지원하는지는 소스와 실제 요청을 따로 검증한다.
- 첫 모델 한정 **source-only 프로필 변경 및 모의 API 테스트 작업**은 별도 브랜치에서 진행 중이며 로컬 B14 1,013개 테스트가 통과했다. **메인 병합 또는 운영 배포 완료라는 의미가 아니다.** 기존 8개 모델의 기본 동작을 먼저 보존한다.
- 무료 프로젝트의 실제 사용 제한은 [Google AI Studio Rate limits](https://aistudio.google.com/rate-limit)에서 해당 키의 프로젝트 기준으로 RPM·TPM·RPD를 읽어 확인해야 한다.

공식 사양: [Gemini 3.1 Flash-Lite](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-flash-lite), [Thinking](https://ai.google.dev/gemini-api/docs/generate-content/thinking), [OpenAI 호환](https://ai.google.dev/gemini-api/docs/openai), [할당량](https://ai.google.dev/gemini-api/docs/rate-limits).

## 6. 모델 하나를 끝내는 검증 순서

1. **공식 사양 확인:** exact 모델 ID, 컨텍스트, 최대 출력, 리즈닝 지원 단계·기본값, 필드 호환성.
2. **실제 티어 확인:** 같은 프로젝트의 실제 RPM·TPM·RPD와 무료/유료 상태. 모르겠으면 `UNKNOWN`.
3. **소스 설정:** B14 JSON 한 모델만 보완하고, 모델별 파라미터를 제공자 요청 형식에 맞춘다. 나머지 모델 동작은 유지.
4. **모의 호출 검사:** 파라미터 생략·명시·오류·지원하지 않는 모델 사용을 모두 검증.
5. **제한된 실제 호출:** 한 모델을 지정해 응답 코드, 사용 토큰, 완료 사유, 지연시간, 모델 ID·경로 일치 여부 기록. 무료 프로젝트의 이용 한도 안에서 진행.
6. **제품 기준 평가:** 10개 견적 추출 시험, 12개 품목, 단가 미정·0원, 정정 문구 및 B66 계산·최종 PDF 연결. 결과를 품질/가용성/PDF 각각 보고.
7. **Owner 판단:** 유지·보완·제외·후보 추가는 실측과 비교 결과를 바탕으로 결정. 한 모델에서 검증한 절차를 다음 모델에 반복한다.

## 7. 결과 보고 표준

각 모델의 보고서는 다음 8개 항목을 포함한다: **모델 ID·제공자 / 공식 입력·출력 능력 / 리즈닝 지원·기본값 / 무료 등급과 RPM·TPM·RPD / API 성공률·429·504 / QKR 정확도 / 제품 PDF 최종 상태 / 미해결 사항·다음 검증**.

결과를 `PASS`, `FAIL`, `UNKNOWN`, `NOT_TESTED`로 명확히 기록한다. 근거 없는 추정과 요청에 없는 주변 주제는 추가하지 않는다.
