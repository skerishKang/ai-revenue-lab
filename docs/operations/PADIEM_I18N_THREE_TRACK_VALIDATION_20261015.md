## 1. 결정

PADIEM 사이트에서 **한국어(ko)를 기능 개발 및 검증 기준 언어**로 사용한다. UI 현지화는 영어(en), 중국어 간체(zh-CN), 일본어(ja)까지 확장하되, **기능 코드·컴포넌트·API/인증·데이터 소스를 언어별로 복제하지 않는다.** 다국어는 기존 단일 기능 위에 번역 리소스를 표시하는 기능으로 설계한다.

테스트는 **F (기능), T (번역), V (시각/화면 구조)**라는 독립된 검증 트랙으로 나눈다. 이것은 기술 구현 지침이며 모든 언어·모든 제품에 대해 전체 E2E 테스트를 곱셈하라는 요구가 아니다.

| 영역 | F: 기능 | T: 번역 품질 | V: 화면 구조 |
| --- | --- | --- | --- |
| 질문 | 실제 기능이 작동하는가? | 원문의 의미가 정확히 전달되는가? | 표시된 문자열 때문에 화면이 깨지는가? |
| 기준 언어 | **ko만 대표 시나리오 실행** | 각 변경된 번역 언어 | 영향받는 언어·화면 |
| 검사 | UI 행동/서버 응답/보안·권한/파일 결과 | 의미·어조·용어, 누락·키·변수·복수형·접근성 문구 | 오버플로·클리핑·겹침·줄바꿈·폰트·반응형 기하 |
| 트리거 | 공유 기능 코드와 실제 위험 경계 변경 | 원문/번역 키·문구 변경 | CSS/레이아웃/폰트 변경, 또는 텍스트 길이 변화가 해당 화면을 위협할 때 |
| 의도적 비대상 | en/zh-CN/ja에서 동일 로그인·모델·검색·견적 E2E 재실행 | 모델 API 호출, 페이지 기능 회귀 | AI 호출·인증·실사용 파일 생성 |
| 결과 기록 | F: PASS/FAIL/NOT_APPLICABLE | T: PASS/FAIL/NOT_APPLICABLE | V: PASS/FAIL/NOT_APPLICABLE |

### 절대적인 핵심 규칙

1. **F PASS가 T/V 실행을 자동 요구하지 않는다.** 한글 기능을 수정했다고 모든 언어의 기능 회귀 테스트를 실행하지 않는다.
2. **T PASS가 F/V 전량 실행을 요구하지 않는다.** 번역 수정은 해당 번역 키·리소스만 검증한다. 넘침 위험이 확인된 화면에 한해 V를 독립 실행할 수 있다.
3. **V PASS가 F/T 전량 실행을 요구하지 않는다.** 시각 테스트는 실제 사용자 데이터·모델·검색·커넥터 작업을 수행하지 않는 고정 fixture/mock 렌더로 구성한다.
4. 한 커밋이 복수 영역을 실질적으로 변경한다면 **변경된 영역만 병렬·독립 검증**한다. 어떤 트랙의 성공도 다른 트랙의 성공으로 가장하지 않는다.
5. 기존 저장소 보안·인증·권한·GitHub 브랜치 필수 체크는 계속 적용한다. 언어별 코드 분기·조건부 권한 처리 등 **기능 자체가 언어에 따라 다를 때만** 관련 언어 차이 경계를 좁게 검사한다.

## 2. 다국어 구현 구조 — 재사용 우선

- 기존 Chat/Claw 공통 화면·테마·locale selector 및 번역 키를 우선 재사용한다. Claw 전용 중복 언어 상태를 만들지 않는다.
- 기존 B62 ko/en URL 권위 계약(#1729)을 깨지 않고 지원 locale을 확장한다. 별도 저장소, 계정, 쿠키 강제, 페이지 복제, 무거운 신규 프레임워크를 기본값으로 추가하지 않는다.
- **단일 사용자 기능 컴포넌트 + 로케일별 문자열 사전**이 기본. 한국어를 원문으로 관리하고 새 키의 번역이 없으면 한국어로 폴백하며 누락을 T 결과에 기록한다.
- 문자열 키/플레이스홀더/복수형/날짜·숫자 형식과 링크·접근성 문구를 UI 레벨에서 번역 가능하게 한다. 원문·번역이 같다는 키 검사만으로 번역 품질 PASS를 주장하지 않는다.
- UI 선택 언어와 사용자가 AI에 질문한 언어, AI 답변 언어, 생성 문서의 언어, 통화, 견적서 법률·세금 조건은 별도 입력/계약이다. 사용자 질문 언어를 화면 locale로 덮어쓰지 않는다.
- 사이트/제품마다 현재 구성과 리소스 상태를 먼저 확인한다. Chat·Claw·B66·회사 사이트 등을 **공통 로케일 방식으로 연결할 후보**로 검토하되 각 제품별 적용 범위를 명시하고 기존 기능을 보존한다.

## 3. 변경 유형에 따른 최소 실행 표

| 변경 | F | T | V |
| --- | --- | --- | --- |
| 모델 라우팅·로그인·검색 로직만 | **ko에서 변경 기능** | 없음 | 없음 |
| 한국어 UI 문구만 | 동작 변화 없으면 없음 | 해당 원문 키 및 연관 번역 검토 | 글자 길이 위험이 있는 해당 컴포넌트만 |
| 영어 번역 키 1개 | 없음 | **해당 en 키만** | 길이/표시 위험이 있는 해당 컴포넌트만 |
| 중국어·일본어 번역 사전 추가 | 없음 | 신규 번역 키·의미·변수 검사 | 신규 언어 도입 대표 화면 기준선, 이후 변경부만 |
| 공통 CSS·폰트·반응형 UI 수정 | 기능 동작이 변경된 경우 관련 ko만 | 원문 번역 자체 변화 없으면 없음 | 영향을 받는 컴포넌트·언어·뷰포트만 |
| 공통 UI 언어 전환 메커니즘 자체 수정 | **변경된 전환 동작만** | 키/번역 변화가 있을 때만 | 배치 위험이 있을 때만 |
| 번역을 포함한 기능/화면 동시 수정 | 변경된 ko 기능만 | 변경된 번역만 | 영향을 받은 화면만 |

위 표는 원칙이며, 실제 변경에서 발생한 고위험 보안·권한·데이터 경계는 공통 운영정책의 해당 테스트가 우선한다.

## 4. 각 트랙의 완료 증거

**F 기능**: 한국어 대표 화면에서 실제 공유 기능 한 번 검증 + 필요한 기존 단위/계약·보안 테스트. 기존 성공 증거가 재사용 가능하면 불필요한 재실행 금지. 국가별 반복 E2E 매트릭스 생성 금지.

**T 번역**: 변경된 키별로 원문→현지화 의미·문맥·어투·용어를 대조하고, 누락/빈 문자열, placeholder 이름·타입·순서, 복수형/치환, 링크, 화면 읽기 보조 텍스트를 정적으로 점검한다. 자동 키 검사와 의미/자연스러움 검토는 별도의 증거로 남긴다. 번역 충실도는 번역 변경 시에만 판단한다.

**V 시각/구조**: 뷰포트와 영향 컴포넌트의 실제 배치·클리핑·넘침·겹침 여부를 검사한다. CSS·폰트·대표 UI가 처음 다국어화될 때 기준선 생성, 이후에는 위험이 발생한 특정 문자열/화면/크기만 확인한다. API와 실데이터에 의존하지 않는 mock/fixture 우선; 픽셀 스냅샷 변경 자체를 기능 오류로 간주하지 않는다.

## 5. CI 설계 가드

- 각 트랙은 독립된 명령/워크플로 또는 명확히 구분된 job 단계·결과를 갖는다. 이름과 트리거에 F/T/V 목적을 표시한다.
- 변경 파일/키/컴포넌트 범위를 기준으로 영향을 받는 잡만 선택한다. T 변경이 F × 4개 언어의 재실행을 유발하지 않게 한다.
- 광범위한 기존 CI fan-out을 발견하면 먼저 기존 job 조건·path filter를 정리한다. **보안상 필수 검사나 실제 GitHub branch protection을 무시하지 않는다.**
- 세 트랙은 독립 결과를 보고하며, 성공 기준은 구체적 검출 결함으로 정의한다. 모든 번역/모든 페이지/모든 뷰포트/모든 제품의 매커니즘 없는 전량 테스트는 금지한다.
- 단순 문서 변경은 저장소 기존 **T0** 규칙대로 링크·내용 범위만 검토한다. 제품 테스트·배포 없음.
