## 이번 관측 결과
1. 브라우저 프로필 연결 후 실제 스타트업 지원서(Typeform **19문항**) 열람 성공.
2. 신청자 이름·이메일·역할·LinkedIn 등 필수 질문에서 여러 차례 새 브라우저 실행을 시작해 동일한 초기 질문을 다시 답함.
3. 사용자와의 과거 대화/기존 공개 프로필 검색으로 회수 가능한 정보도 매번 확인 질문을 해 불필요한 중단이 발생.
4. 신청자 LinkedIn 항목에서 문항의 성격을 맞게 확인했으나 응답이 지연되고 사용자에게 현재 입력 위치와 진척을 충분히 전달하지 못함.
5. 사용자 요청: '이따 나랑 Tabbit으로 같이 하자' → 공동 화면 확인 방식 선호. **신청 제출 미확인**; 실제 제출 성공 증거 없음.
6. 중단 시 상태 설명에 실행 중인 웹 자동화 세션의 종료 여부를 명확히 검증하지 못함.
7. 원인: 프로젝트 맥락/이전 답변 기반 데이터 재사용 불충분, 매 실행 새 폼 시작, 단계별 상태 저장/재개 부재, 폼 제출/취소 상태의 증거 부족. 서비스 자체의 결함으로 단정하지 않음.

## 개선 실행 규칙
- **시작 전 자료 수집:** 사용자가 이미 제공한 값과 공개 검증 가능한 회사 정보부터 정리. 알려진 사실을 재질문하지 않는다.
- **신원 일치 확인:** 동명이인 가능성이 있는 LinkedIn 등은 정확한 사용자 본인 프로필인지 출처 2개 이상과 회사·경력의 교집합으로 식별. 출처 불충분하면 1회 질문.
- **폼 필드 인벤토리:** 가능하면 먼저 전체 질문, required/optional, 선택지, 개인정보·계약/과금 조항을 파악하고 간단한 답변 매핑을 만든다.
- **진행 중 상태 추적:** 질문 번호, 마지막 완료된 항목, 미확정 값, 제출 여부를 기록. 브라우저 재시작 시 중복 제출 금지. 플랫폼의 임시저장이 실제 되는지는 확인한다.
- **사용자 개입:** 정말 필요한 한두 가지 정보만 질문. 예: 자금조달 근거, 증빙, 동의/계약 조건. 신청자 성명·이메일처럼 이미 받은 값은 다시 묻지 않는다.
- **자동화 안전:** 비밀번호·일회용코드·쿠키·API 키·민감 계정 데이터는 로그/이슈/프롬프트에 노출하지 않는다. 외부 제출·구매·약관 동의는 사용자가 승인한 업무 범위를 지킨다.
- **브라우저 세션 제어:** 사용자가 중단 요청 시 실제 실행 중인 Run이 있는지 확인하고 도구가 지원하면 취소 후 결과를 증거로 보고. 취소 미확인은 '미확인'으로 표기.
- **검증 단계 구분:** `FORM_OPENED`, `FIELDS_FILLED`, `SUBMITTED`, `RECEIPT_CONFIRMED`를 구분하며 제출 전 성공 선언 금지.
- **공동 실습:** 사용자가 Tabbit 공동 진행을 선택하면 화면을 함께 보며 필드별 입력과 제출 직전 내용을 확인하도록 운영. 회차마다 관찰한 실수와 개선점을 이 문서에 누적할 수 있다.
