## 1. 핵심 제품 계약: 한 개의 회의 기능, 두 개의 진입점

1. **대화형**: 사용자가 PADIEM CLAW에 ‘회의할 테니 회의록 준비해 줘’라고 말하면 기존 Claw 대화의 맥락으로 회의 준비/진행 UI를 열고, 회의 세션을 생성하거나 재개한다.
2. **왼쪽 회의록 메뉴**: 같은 Claw 공통 사이드바의 ‘회의록’ 화면에서 새 회의, 현재 진행 중인 회의, 과거 회의·전사문·회의록·후속 작업을 조회한다.
3. 두 진입점은 동일한 **meeting_session_id, 기존 PADIEM 로그인/워크스페이스 권한, 파일 메타데이터, capture/STT 엔진**을 이용한다. 새 회의록 서버·별도 로그인·두 번째 저장소나 모델 라우터를 만들지 않는다.
4. 기존 Chat·Claw 공통 녹음/전사 UI 프리미티브는 재사용할 수 있으나, #4643의 **짧은 마이크 입력→메시지 작성/전송**과 이번 **장시간 회의 세션 기록**은 별도의 사용자 동작이다. 회의 발언마다 Chat/Claw 모델로 자동 발송하지 않는다.

## 2. 세 가지 회의 시작 모드

| 선택 | 실제 동작 | Drive 원본 | 전사 |
| --- | --- | --- | --- |
| A. 녹음만 | 마이크 입력을 오디오 파일로 기록 | **저장** | 실행 안 함; 회의 종료 후 사용자가 요청하면 별도 전사 가능 |
| B. 실시간 전사만 | 마이크 발언을 시간 흐름대로 텍스트로 기록 | **오디오 파일 생성하지 않음** | **저장** |
| C. 녹음 + 실시간 전사 | 동일한 회의 세션에서 녹음과 받아쓰기를 병행 | **저장** | **저장** |

- ‘회의록 준비해 줘’ 요청만으로 몰래 녹음/전사를 시작하지 않는다. **세 모드 중 하나를 선택하고 [회의 시작]을 누른 뒤** 브라우저/OS 마이크 사용 권한을 얻는다. 시작·녹음 중·일시 정지·종료 상태는 화면에 명확히 표시한다.
- ‘녹음’은 오디오 원본을 생성하는 행위, ‘전사’는 음성을 문자로 바꾸는 행위, ‘회의록 생성’은 전사문을 AI가 요약/구조화하는 행위다. 서로 다른 상태·완료 증거로 유지한다.
- 회의 종료 전후 사용자의 요청에 따라 **전사 원문/회의록/결정사항/담당자별 할 일**을 생성할 수 있다. AI가 만든 회의록은 실제 발언의 원문 근거와 수정 가능한 초안으로 취급한다.
- 녹음 없이 전사만 선택했을 경우 회의 후 오디오 재생이나 재전사는 할 수 없다는 사실을 표시한다. 실시간 전사에 누락/끊김이 발생해도 임의로 원음을 복원했다고 주장하지 않는다.

## 3. STT 기술 구분 — ‘무료/무제한’ 혼동 방지

| 경로 | 용도 | PADIEM API 키 | 비용/한도에 관한 올바른 표현 |
| --- | --- | --- | --- |
| **브라우저 Web Speech API / SpeechRecognition** | 지원 브라우저에서 즉시 받아쓰기 | 보통 별도 PADIEM STT API 키 불필요 | 브라우저 제공 기능. PADIEM이 직접 모델 API 과금하지 않을 수 있으나 **무제한·무중단·전 브라우저 지원을 보증하지 않는다** |
| **Gemini/Google 모델 기반 스트리밍 STT** | 별도 실시간 오디오 모델 경로가 필요할 때 | **서버의 PADIEM 관리 키** | 모델·계정별 무료 등급·과금·Rate Limit·세션 한도는 별개이며 현재 실제 등록/승인 라우팅 기준 확인 |
| **파일 업로드 후 배치 전사** | 녹음 완료 후 정확한 재전사·장시간 파일 처리 | PADIEM 관리 키를 쓰는 경우 | 실시간 STT와 파일 한도·과금·입력 형식이 다름; 한쪽 제한을 다른 쪽에 그대로 적용하지 않는다 |

- 기존 #4643 및 Global Classroom의 실제 STT·발화 식별/중복 방지 코드를 **재사용 우선**한다. 새로운 실시간 인식 제공자를 무단 활성화하거나 특정 상품명을 현행 등록 모델로 추정하지 않는다.
- **브라우저 SpeechRecognition 자체가 Google 모델 API라는 뜻은 아니다.** Chrome 등의 브라우저 인식 서비스는 음성을 외부 인식 서비스로 보낼 수 있다. 실제 지원/서비스 전송/오프라인 여부를 브라우저 기능별로 구분해 안내한다.
- 제공자 장애·세션 제한으로 STT가 중단돼도 **녹음이 활성화된 경우 오디오 기록은 독립적으로 계속**되도록 설계한다. 실패한 STT 구간은 ‘미전사’로 표시하고 필요 시 저장된 원본으로 후처리 전사를 제안한다.
- **Google 무료 STT 무제한이라는 사업/기술 전제를 만들지 않는다.** 실제 모델/API별 무료 자격·할당량·개인정보 처리 조건은 착수 시 공식 자료와 실제 PADIEM 계정에서 확인한다.

외부 기술 근거:
- MDN Web Speech API: https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition
- Google Gemini Live API: https://ai.google.dev/gemini-api/docs/live-api/best-practices

## 4. 저장 계약: 원본은 사용자의 Google Drive

- 모든 모드의 기본 저장지는 로그인 사용자에게 권한이 있는 **본인의 Google Drive**. 녹음 오디오·영상 원본은 PADIEM 서버/DB에 영구 저장하지 않는다.
- 브라우저/클라이언트가 사용자 Google OAuth 권한으로 Drive의 공식 resumable upload를 활용해 업로드하도록 설계한다. 실제 구현 단계에서는 인증/토큰 처리·권한 범위·CORS와 긴 녹음의 메모리 점유를 검증한다. **PADIEM 서버를 원본의 이중 업로드 릴레이로 만들지 않는다.**
- PADIEM DB에는 기존 서버 검증 소유자·워크스페이스 식별, meeting_session_id, Drive file ID, 파일 MIME/상태/작업 메타데이터만 최소 저장한다. 다른 고객 Drive를 연결/조회할 수 없다.
- 녹음 오디오, 전사 TXT, AI 회의록은 동일 회의 ID로 연결하고, 전사 원문·최종 회의록 결과도 사용자 Drive에 저장할 수 있게 한다. 사용자가 원본/전사/결과를 확인·내보내고 정리할 수 있어야 한다.
- 네트워크 불량·Drive 용량 초과·토큰 만료 시 **저장 실패를 성공으로 보이지 않는다**. 가능한 경우 사용자 기기의 안전한 임시 보존/다운로드·재개 경로를 제시한다. 사용자 Drive에 기록되기 전에 데이터가 분실되지 않는 설계가 필요하다.
- 세션별 녹음/전사 진행 중 표시, 종료/삭제, 브라우저 권한, 참여자에 대한 필요한 고지·동의 등 실제 사용 환경과 권한을 반영한다. 사용자가 모르게 백그라운드로 녹음을 시작하지 않는다.

Drive 기술 근거: https://developers.google.com/workspace/drive/api/guides/manage-uploads

## 5. 회의록 페이지 UI와 Claw 기능 분담

- 공통 회의 세션 서비스가 **현재 회의 상태·녹음/전사 진행·요약 작업·Drive 저장 상태**를 관리한다.
- **Claw 대화 경로**: 자연어로 회의 준비, 모드 선택 열기, 회의록 생성/수정, 할 일 추출, Calendar 연계 요청.
- **왼쪽 회의록 페이지**: 새 회의/진행 중 회의/과거 회의, 원본 듣기(녹음한 경우), 전사 원문 보기·편집, 회의록 확인, Drive 저장/오류 상태, 후속 업무 관리.
- 같은 회의를 두 화면에서 열어도 **녹음 두 개나 업로드 두 번을 만들지 않는다**. 둘 다 같은 세션의 단일 시작·중지 권위를 공유한다.
- 회의 관련 후속 작업은 기존 PADIEM Calendar(#2834)의 검증된 도구·권한을 재사용한다. 과거 #4647의 업로드 후 후처리·캘린더 후보 기능을 버리지 않고 추가한다.
- 사진/카메라·영상 회의 캡처는 위 capture/Drive 권한 컴포넌트의 향후 확장 후보이나, 처음부터 실시간 비전 스트림과 녹음/전사 MVP를 한 번에 강제하지 않는다.

## 6. 다음 구현과 최소 수용 기준

1. 기존 #4643 실시간 STT, #4647 파일 전사, Chat/Claw 공통 프레임·Drive OAuth/파일 ID 저장 경로를 먼저 확인하고 재사용한다.
2. 동일 세션의 3 모드와 **대화/메뉴 두 진입점**을 연결한다. 서로 다른 서비스·세션·저장소를 만들지 않는다.
3. 3개 모드의 실제 작동은 각각 한 번씩 좁은 수용 시나리오로 확인하며, 그 외 언어/브라우저/제품마다 전체 회귀를 반복하지 않는다. 실제 위험이 있는 브라우저별 권한·기기 차이만 추가 확인한다.
4. 녹음만: 오디오 Drive readback, 불필요한 STT 호출 0 / 전사만: 오디오 생성 0, 텍스트 정확한 파일 readback / 동시 모드: 서로 독립 진행 및 원본+전사 연결 확인.
5. Drive 업로드 실패·STT 오류·녹음 중단의 **부분 성공** 표시, 계정/고객사 데이터 격리, 시작/정지·사용자 삭제/내보내기 확인.
6. 작성된 회의록/후속 일정 후보는 실제 원문 근거를 유지하고, Calendar 실제 쓰기는 현재 서버 권한·제품 계약에 따라 실행한다.

## 7. 범위 선언

- 이 문서는 **새 개발 방향 및 STT 혼동 방지 기준**을 기록한다. 제품 구현·최종 UX·Google API 무료 사용 무제한·현재 운영 서비스 완성 상태를 선언하지 않는다.
- 로컬 비공개 사업방침·운영방침은 별도 COM1 Governance를 실제 열람한다. 본 공개 문서에 비공개 원문을 옮기지 않는다.
- 제품 코드/CI/Cloudflare 운영 설정/실사용 Drive 파일에는 이 문서 작업만으로 변화를 주지 않는다.

## 8. 2026-10-16 기존 Draft PR #4813의 최신 main 선택 이식

- 대표가 확정한 순서 **채팅·Claw / 회의록 → 자동화 → 라이브러리 → 캘린더 / Connectors → Skills**를 최신 B62 사이드바에 적용한다. 미구현 항목은 비활성 상태를 표시하며 권한 없는 기능을 새로 활성화하지 않는다.
- 회의록은 별도 팝업이나 사이트가 아닌 동일 app-shell의 main-panel 안의 중앙 meetingView로 표시한다. 기존 Draft에는 main 외부에 있던 화면을 최신 main으로 이식하면서 수정했다.
- 브라우저 표준 녹음(MediaRecorder), 전사(SpeechRecognition), 동시 진행과 로컬 원본/TXT 다운로드를 재사용한다. Claw 자연어 준비 요청과 사이드바 메뉴는 동일 화면을 연다.
- 회의 장시간 내용은 메인 패널 내부만 스크롤한다. 기존 Chat/Claw 대화의 독립 최근 대화 스크롤과 계정 하단 고정은 보존한다.
- Google Drive 저장 UI와 서버의 사용자별 resumable 세션 계약을 준비했다. **Control Plane 검증 WRITE 세션 포트가 없는 운영 환경에서는 HTTP 503**이 맞으며 로컬 다운로드 안내를 표시한다. 실제 파일 업로드·readback이 성공하기 전까지 Drive 저장 완료라고 말하지 않는다.
- 이 이식은 #4647 이슈를 대체하거나 완료 처리하지 않는다. 실제 고객 Drive 업로드, 고객 기기 마이크 E2E, 영속 회의 목록·Calendar 후속 연결은 #4647 완료 조건으로 남긴다.
