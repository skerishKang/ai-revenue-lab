## 1. 샘플의 성격

10건은 **전부 이 실증을 위해 만든 합성 데이터**다. 제조사·공급사·품목·가격을
모두 가상의 값으로 지었다. 어떤 고객의 실제 품목목록·가격표·거래처 정보도
이 저장소에도 이 문서에도 없다.

원본은 공급처가 실제로 넘겨주는 형태를 의식해 일부러 어지럽게 만들었다.

| 원본의 흉내 | 예 |
|---|---|
| 앞뒤 공백과 중복 공백 | ` 볼  베어링  6205-2RS ` |
| 소문자 코드와 코드 안 공백 | ` brg-6205-01 ` |
| 전각 숫자 | `알루미늄 ４０x４０ 프로파일` |
| 통화 기호가 붙은 금액 | `8,500원` |
| 천단위 구분기호 | `1,200` |
| 금액 칸이 비어 있음 | 기어오일의 매입가 |
| 숫자가 아닌 금액 | `문의` |
| 코드가 비어 있음 | 알루미늄 프로파일 |
| 매핑되지 않는 열 | `담당자` |

**셀 단위로 같은 값**이며, 회귀 테스트가 이 일치를 확인한다.

## 3. 처리 전·후 (10건 전체)

`원본` 열은 원본 파일의 값, `정규화` 열은 정리된 값이다. `→`가 있는 칸은
정규화가 들어간 곳이다.

| 행 | 품목코드 | 상품명 | 매입가 | 단위 | 결과 |
|---|---|---|---|---|---|
| 2 | ` brg-6205-01 ` → `BRG-6205-01` | ` 볼  베어링  6205-2RS ` → `볼 베어링 6205-2RS` | `8,500원` → `8500` | EA | 자동 확정 |
| 3 | `HOS-0150-01` | `유압호스 조립체` | `32000` | 본 | 자동 확정 |
| 4 | `BLT-M8-30-A` | `스테인리스 육각볼트 M8x30` | `1,200` → `1200` | EA | 자동 확정 |
| 5 | `SEN-018N-01` | `포토센서 NPN 18mm` | `18000` | EA | 중복(코드 동일, 11행과) |
| 6 | `OIL-VG220-18` | `기어오일 ISO VG 220` | (비어 있음) → (비어 있음) | 드럼 | 사람 확인: 매입가 누락 |
| 7 | `BLT-A45-000` | `A형 벨트 A-45` | `문의` → (비어 있음) | EA | 사람 확인: 매입가 판독 불가 |
| 8 | (비어 있음) → (비어 있음) | `알루미늄 ４０x４０ 프로파일` → `알루미늄 40x40 프로파일` | `6800` | 본 | 사람 확인: 품목코드 없음 |
| 9 | `CAL-0150-00` | `디지털 캘리퍼스 150mm` | `28000` | EA | 사람 확인: AI 공급사 신뢰도 낮음 + 이름 유사 중복 |
| 10 | `CAL-0150-01` | `디지털 캘리퍼스 150mm 정밀` | `27500` | EA | 사람 확인: 이름 유사 중복 |
| 11 | `SEN-018N-01` | `포토센서 NPN 18mm` | `18000` | EA | 중복(코드 동일, 5행과) |

### 이 결과가 말하는 것

1. **값을 만들어내지 않았다.** 비어 있던 매입가는 비어 있는 채로 남았고,
   `문의`는 숫자가 아니므로 빈칸이 되고 그 사실이 검토 사유로 기록되었다.
2. **기계적으로 정리할 수 있는 것을 정리했다.** 코드 대소문자, 코드 공백,
   이름 공백, 전각 숫자, 통화 기호, 천단위 구분기호가 모두 정리되었다.
   그 3건은 그대로 이관 파일에 들어갔다.
3. **판단이 필요한 것을 사람에게 남겼다.** 중복, 누락, 판독 불가, 낮은 신뢰도.
   7건은 사유가 붙은 상태로 검토 목록에 들어갔다.
4. **AI 추출은 빈칸만 채우고, 금액은 만들지 못했다.** 9행의 공급사는
   비어 있던 칸을 채웠지만 신뢰도가 0.72라 사람이 확인하도록 표시했다.
   같은 추출 결과가 판매가와 매입가를 제안했지만 **필드 이름으로 거절**되었고,
   거절 사유가 파일의 오류 열에 남았다.

## 6. 중복·오류 발생 건수

| 종류 | 건수 | 판정 방식 |
|---|---|---|
| 동일 품목코드 | 1건 (2행) | 코드가 같으면 같은 ERP 행이므로 자동 판정 |
| 이름·규격·단위 동일 | 0건 | 정규화된 이름·규격·단위가 모두 같을 때 자동 판정 |
| 이름 유사 후보 | 1건 (2행) | 이름 유사도 0.9231, 기준 0.92. **후보이며 판정이 아니다** |
| 원본 값 판독 오류 | 2건 | AI가 생성한 가격 2건을 필드 이름으로 거절 |
| 매핑되지 않은 원본 열 | 1건 | `담당자` — 정규화 레코드에 넣지 않고 보고만 함 |

중복 그룹 안의 행은 기준 행과 대상 행으로 나뉘고, **그룹 전체가 사람 확인 대상으로
남는다.** 어느 쪽을 남길지는 사람이 정한다.

파일 기록이 전체의 대부분을 차지한다. 10건 규모에서는 사람이 확인하기에

## 8. 규모 측정 — 대규모 카탈로그 처리 가능성

합성 20,000행과 30,000행으로 규모를 재현해 측정했다.

```bash
python apps/erp-item-master/scripts/scale_check.py --rows 30000
```

| 단계 | 30,000행 | 비고 |
|---|---|---|
| 원본 읽기 | 0.4초 | CSV |
| 정규화 | 3.7초 | |
| 중복 탐지 | 2.8초 | 비교한 이름 쌍 8,284개, 건너뛴 블록 2개 |
| 검토 판정 | 0.4초 | |
| 파일 기록 | 32.4초 | 8개 시트 Excel 워크북 |
| **합계** | **39.7초** | **초당 756행** |

### 이 측정으로 말할 수 있는 것

- **정규화·중복·검토 단계는 30,000행에서 10초 이내**에 끝난다. 처리 비용의 대부분이
  사람이 보는 검토 워크북을 만드는 쪽이다.
- ERP 이관에 실제로 필요한 파일은 CSV 한 장이므로, Excel 기록을 빼면
  30,000행 기준 약 **7.3초**다.
- 20,000행은 16.3초(초당 1,230행), 30,000행은 39.7초(초당 756행)였다. 별도 장비나
  별도 운영 체계가 필요 없다. 이 측정은 COM2 사양의 머신에서 돌았다.

### 이 측정으로 말할 수 없는 것

- **이카운트 서버가 수만 건을 받는지**는 서버 제약이다. 이 측정과 무관하다.
- **실데이터의 처리시간과 오류율**은 표본이 다르면 달라진다. 이 합성 표본의
  자동 확정 비율(3/10)은 실데이터의 비율이 아니다.
- **Excel 1회 업로드 행 수 상한**이 공개되지 않았으므로, 수만 건을 몇 파일로 나눠야
  하는지는 공식 확인이 필요하다.

### 이번 실증에서 고친 것

첫 측정에서 중복 탐색이 2,000행에 18초가 걸렸다. 차단 키가 이름 앞 2글자뿐이어서
대부분의 행이 한 블록에 몰렸기 때문이다. 차단 키를 **단위 + 이름 속 숫자 + 앞 4글자 +
뒤 4글자**로 넓히고, 블록 크기 상한을 두고, 길이 차이가 큰 쌍을 비교 전에 제외했다.
같은 2,000행에서 중복 탐색은 그 뒤 1초 안으로 내려갔고, 30,000행 전체가 39.7초에
끝났다.
