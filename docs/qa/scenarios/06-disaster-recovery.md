# ⑥ 장애 복구

**목적:** 오프사이트 백업을 임시 폴더에 복원해 조회 가능 여부를 확인합니다. 운영 서버에는 접속하지 않습니다.  
**사전 조건:** 컴2 레인에서만 실행합니다. 로컬 백업과 복호화 키 파일이 필요하며 경로는 환경 변수로 받습니다.

| 단계 | 사용자 동작 → 기대 화면·응답 | 확인 지표 | 튜토리얼 캡션 |
|---|---|---|---|
| 1 | 격리된 임시 복원 경로 만들기 → 복원이 그 경로를 대상으로 함 | 복원 상태·ms | 백업을 별도 임시 경로에 복원해요. |
| 2 | 복원 데이터 경로로 Chat 실행 → 로컬 인스턴스 준비 | 프로세스 상태·ms | 복원한 데이터로 Chat을 실행해요. |
| 3 | GET /와 GET /health만 확인 → 화면과 상태 응답 | 상태 코드·ms·504 여부 | 화면과 상태 응답을 확인해요. |
| 4 | 임시 인스턴스 닫기 → 복원 폴더는 운영 데이터와 분리 | 종료 상태·ms | 임시 확인을 마치고 인스턴스를 닫아요. |

deploy/host-com2/offsite-backup/run_live_chat_restore.sh를 사용합니다. COM2_OFFSITE_KEY_FILE과 COM2_OFFSITE_KEY_ID는 환경 변수로만 제공합니다. 이 기계에서는 실행하지 않습니다.

## 스크립트가 스스로 지키는 것 (#6737)

| 항목 | 동작 |
|---|---|
| 복원 대상 | 임시 폴더의 `chat.sqlite3` 파일 하나. `offsite.py restore --target`은 파일 경로를 받습니다. |
| 운영 경로 | `/var/lib/padiem`, `/opt/padiem`, `/srv/padiem`, `/mnt/c`·`/mnt/d` 등은 인자로 주면 거부합니다. `PADIEM_CHAT_LOCAL_DATA_DIR`를 물려받아도 거부합니다. |
| 포트 | 시험 Chat은 고정 `127.0.0.1:18798`. 이미 쓰이면 다른 포트로 바꾸지 않고 실패합니다. |
| 상류 | 큐 18797, P01 18811, B14 18789의 닫힌 루프백 포트로 치환합니다. cloudflared를 띄우지 않고, 프록시 환경 변수도 지웁니다. |
| 환경 파일 | `PADIEM_RESTORE_ENV_FILE`은 `source`하지 않고 키·값으로만 읽습니다. 값에 `$`가 있어도 그대로 남고, 값은 어떤 경로에서도 출력하지 않습니다. systemd에서 돌릴 때는 `systemd-run --property=EnvironmentFile=`로 넘깁니다. |
| 종료 | `trap`이 시험 Chat을 끄고 포트가 닫혔는지 확인합니다. 닫히지 않으면 실행을 실패로 끝냅니다. |
| 확인 | `PRAGMA integrity_check`, `foreign_key_check` 위반 수, 마이그레이션 장부 마지막 번호, 주요 테이블 행 수(숫자), 구간별 ms를 출력합니다. |

예상 소요: 데이터 복원은 스냅샷 크기에 비례해 수 초, Chat 기동과 상태 확인은 10~30초입니다. 배포·터널 전환 시간은 별도이며 이 스크립트에 포함되지 않습니다.
