# Measurement Framework

## 1. Purpose

The project must distinguish a compelling demonstration from an economically meaningful result. Every experiment should record production inputs, user behavior, and revenue outputs in a consistent format.

## 2. Required input measures

- experiment identifier and dates;
- product track;
- number of source records or user inputs;
- free-model calls by provider and model;
- paid-model calls and cost;
- local-compute usage where measurable;
- infrastructure cash cost;
- human work time by activity;
- number of generated candidates;
- number of accepted and published outputs;
- number of rejected or corrected outputs.

## 3. Required quality measures

Depending on the task:

- structured-output success rate;
- source-faithfulness error rate;
- factual contradiction rate;
- duplicate rate;
- continuity error rate;
- user-reported error rate;
- human correction minutes per accepted output;
- provider/model failure rate.

## 4. Required user measures

Depending on the product:

- impressions;
- opens;
- reads or completion;
- saves;
- follows;
- explicit likes and dislikes;
- direction-change requests;
- next-edition requests;
- return rate;
- sharing;
- subscription or purchase intent.

## 5. Required revenue measures

- gross revenue;
- refunds;
- net attributable revenue;
- advertising revenue;
- affiliate clicks and conversions;
- subscription revenue;
- one-time purchase revenue;
- licensing or B2B revenue.

## 6. Core economic indicators

Calculate when data is available:

- revenue per 1,000 AI calls;
- revenue per published output;
- revenue per active user;
- revenue per human hour;
- cash cost per accepted output;
- correction time per accepted output;
- free-to-paid inference ratio;
- payback period for any paid infrastructure.

## 7. Evidence rule

A result must link to reproducible evidence where possible:

- source samples;
- model configuration;
- prompts or prompt version identifiers;
- generated outputs;
- acceptance and rejection decisions;
- test logs;
- analytics export or screenshots;
- payment or affiliate evidence with sensitive details removed.

## 8. Interpretation rule

The first objective is not high revenue. It is to demonstrate a causal path from abundant AI production to a user action with economic value.

A small first payment may be strategically important when:

- cash production cost is near zero;
- the output would be uneconomic for a human team to produce;
- the process is repeatable;
- the user paid for the product rather than for generic AI access.

## 9. Failure is a valid result

Experiments should record negative outcomes. Producing large quantities of content that receive no attention does not demonstrate AI productivity. It demonstrates production without value.

The project should preserve failed experiments so that future work can distinguish:

- production failure;
- quality failure;
- packaging failure;
- distribution failure;
- pricing failure;
- absence of real demand.
