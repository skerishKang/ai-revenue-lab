# PC 레인 고정 마감 폐지 설계 — 2026-10-26

Owner 결정(2026-10-26 새벽), 추적 #5573. **설계이며 구현 완료를 뜻하지 않습니다.** 실행 시한·크기·전송 정책 변경은 후속 PR에서 구현합니다.

## 1. 실행 흐름

1. **Probe**: 승인된 기기·경로에서 읽기는 파일 크기, 목록은 개수(탐색 상한 10,000개), 명령은 종류를 확인합니다. 상한에 도달하면 전체 개수 미확정으로 표시합니다. Probe가 내용 읽기 권한을 만들지는 않습니다.
2. **예측**: 크기 × 기기별 실측 단위 처리 시간으로 계산합니다(bytes/second 속도라면 크기 ÷ 속도). 측정 전에는 보수적 기본값, 이후에는 실측 보정을 사용합니다. 기본값 수치는 후속 구현에서 정합니다.
3. **질문**: 120초 초과 예상이면 기존 `confirmed` 확인 절차로 사용자에게 진행 여부를 묻습니다. 승인은 해당 run·기기·범위에 묶이며 권한이나 ceiling을 넓히지 않습니다.
4. **진행**: 승인 뒤 고정 시간 상한 없이 실행하고 단계·경과·부분 결과를 표시합니다. 예측 초과 시 알림과 취소 수단을 제공하며 자동 실패·503·재실행으로 바꾸지 않습니다.
5. **오프라인**: 실행기 하트비트로 판정합니다. 전송 keep-alive는 실행기 생존·진척·성공의 증거가 아닙니다. 실제 실패·오프라인·취소는 코드와 사용자 문장으로 표시합니다.

## 2. 크기와 목록

- 20MB까지 Worker 경로, 그 이상은 조각 읽기 또는 컴2 경로로 처리합니다. 새 권한을 자동 부여하지 않고 조각 순서·무결성·완료 여부를 검증합니다.
- 목록은 첫 200개와 “더 있음” 표시를 반환하고 페이지로 이어갑니다. 페이지는 동일 기기·루트·run ceiling에 묶습니다. 10,000개 탐색 상한에 도달한 결과를 전체 완료로 표시하지 않습니다.
- 부분 결과·중단·잔여 작업을 명시하며 조용히 절단하지 않습니다.

## 3. 적용 대상

키워드 진입 제거 완료: #5751 — 모델의 도구 선택으로 PC 레인에 진입합니다.
PC run 기록은 `claw_run_history` 단일이며, 자동화 장부 `claw_runs`와 그 소비자는 변경하지 않습니다.

| 대상 | 현재 제약/검토 기준 | 후속 구현 |
| --- | --- | --- |
| PC 핸들러 | ToolSpec 300초 | 고정 마감 제거, 생존·취소·실패 처리 |
| Core idle | 900/1800초 설정 경로 | 생존·진척 구분 재설계, heartbeat를 진척으로 취급하지 않음 |

| 서버 권한 검사 | 소유자·워크스페이스·기기·경로·ceiling·멱등성 | **비대상: 유지** |

## 4. 후속 수용 기준

- 120초 초과 예상 시 확인 전 dispatch 없음, 승인 뒤 동일 run 실행.
- 목록 ceiling에서는 probe·조각 읽기·취소·복구를 통해서도 read dispatch 0.
- 장시간 진행·경과·초과 알림 유지, 실제 실패·취소는 정확한 종료 상태 기록.
- 20MB 경계·조각 무결성·200개 페이지/10,000개 탐색 상한·오프라인·재접속·멱등성을 기존 테스트에 추가.
