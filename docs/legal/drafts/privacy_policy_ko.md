## 1. 총칙

PADIEM(이하 "서비스")은 이용자의 개인정보를 소중하게 다룹니다. 이 방침은 서비스가 어떤 정보를 모으고, 어떤 목적으로 쓰며, 어디에 두고, 언제까지 두는지를 설명합니다.

- 상호: [대표 결정: 판매 주체 상호]
- 개인정보 보호책임자: [대표 결정: 성명·연락처]

## 2. 수집하는 항목과 목적

| 수집 항목 | 내용 | 목적 |
|---|---|---|
| 계정 정보 | 공통 로그인 계정(로그인 제공자의 식별자, 이메일, 표시 이름, 프로필 사진 주소) | 로그인·계정 식별·서비스 제공 |
| 대화 내용 | 이용자가 서비스에서 나눈 대화와 대화 제목 | 대화 저장·이어 보기·검색 |
| 첨부 파일 | 이용자가 대화에 첨부한 문서·이미지 등 | 문서 분석·답변 생성 |
| 프로젝트 파일 | 이용자가 올린 프로젝트 파일의 원본과 추출 텍스트 | 문서 작성·견적 지원 |
| PC 작업 기록 | 처리 건수 형태의 기록(내용 없는 카운터) | 작업 진행 표시·상태 확인 |
| PC 화면 캡처 | 브라우저 화면 캡처 이미지 | 이용자가 맡긴 PC 작업의 확인 |
| 컴퓨터 사용 입력값 | 이용자가 승인한 동작에 쓰는 입력값 | 해당 동작 1회 수행(기록·재사용 없음) |
| 북AI 기록 | 독서 진행·메모·하이라이트·AI 대화 기록 | 북AI 기능 제공 |
| BYOK 키 | 이용자가 등록한 외부 AI 공급사 API 키 | 이용자의 키로 AI 호출(암호화 봉인 보관) |
| 알림 설정 | 메일·텔레그램·디스코드 알림에 쓰는 주소·채널 정보 | 가입 알림·비밀번호 재설정 안내 발송 |

서비스는 이용자가 맡긴 일을 처리하기 위해 필요한 범위 안에서만 위 항목을 모읍니다.

## 3. PC 데이터는 어떻게 다뤄지는지

3.1 PC 작업은 이용자가 사전에 맡긴 범위에서 자동 실행되며, 기본은 최대 권한, 비밀번호 입력·계정 권한 변경·되돌릴 수 없는 삭제·외부 발송만 실행 전 확인, 끄기·일시중지·연결 해제·제거는 언제든 가능합니다.

3.2 PC 작업 기록은 파일 경로·명령 인수·출력 내용이 포함되지 않는 건수 형태로만 남습니다.

3.3 컴퓨터 사용 입력값은 확인한 동작에 1회 전달되며 재사용하지 않고, 세션 재개 시 이전 폼 입력을 되살리지 않습니다.

3.4 파일을 변경하기 전 원본은 이용자 PC의 숨김 폴더(`.padiem-backup`)에 복사됩니다. 이 사본은 이용자 PC에 남으며 서비스 저장소로 옮겨지지 않습니다.

3.5 PC 화면 캡처는 이용자 PC에 저장되고, 캡처를 요청한 계정의 세션으로만 조회할 수 있습니다.

## 4. 보관 위치와 처리하는 곳(처리 위탁)

| 구분 | 역할 | 두는 곳 |
|---|---|---|
| 자체 서버 | 서비스 운영 서버, 파일 원본 처리, 북AI 기록 | 자체 서버(운영 컴퓨터) |
| Cloudflare | 서비스 앞단(웹 요청 처리), 로그인 데이터(D1), 워크스페이스 파일 객체(R2), 외부 백업 | Cloudflare |
| 외부 AI 모델 공급사 | 이용자의 대화 내용을 답변 생성에 사용하기 위해 전송 | 각 공급사 |
| 메일 발송 서비스(Resend) | 비밀번호 재설정 안내 등 메일 발송 | Resend |

- 대화 내용은 답변 생성을 위해 외부 AI 모델 공급사로 전송됩니다. 이용자가 등록한 BYOK 키를 쓸 때는 해당 키가 선택한 공급사로 직접 전송됩니다.
- 관리자 알림(텔레그램·디스코드)은 새 회원가입 접수 같은 운영 알림만 담으며, 고객의 이메일 주소나 문서 내용은 알림 본문에 넣지 않습니다.
- 자체 서버의 데이터는 매일 암호화되어 Cloudflare R2로 백업됩니다. 백업 암호화 키는 자체 서버에만 두고 업로드하지 않습니다.

## 5. 보관 기간

| 항목 | 보관 기간 |
|---|---|
| 대화·첨부·프로젝트 파일 | 이용자가 삭제할 때까지. 삭제 기능: 대화 삭제, 프로젝트 삭제 |
| 서비스에서 만든 문서 | 만든 날부터 30일 |
| PC 작업 기록(카운터) | [대표 결정: 보관 기간] |
| PC 화면 캡처 | [대표 결정: 보관 기간] |
| 북AI 기록 | 이용자가 삭제할 때까지 |
| BYOK 키 | 이용자가 삭제하거나 바꿀 때까지(암호화 봉인 상태로 보관) |
| 만료 속성을 둔 임시 데이터(작업 임시 저장·선택값·승인 대기 등) | 데이터마다 정해진 만료 시각까지 |
| 로그인 확인 캐시 | 최대 30초 |
| 백업(.padiem-backup, 외부 백업) | [대표 결정: 보관 기간] |

코드에 만료 속성(expires_at)은 있지만 자동 삭제 실행 경로가 확인되지 않은 데이터의 최종 파기 시점은 [대표 결정: 파기 시점]에서 정합니다.

## 7. 파기

7.1 이용자가 서비스 안에서 대화·프로젝트를 삭제하면 해당 데이터는 삭제 기능에 따라 지워집니다.

7.2 보관 기간이 끝난 정보나 처리 목적이 끝난 정보는 복구가 어렵도록 지웁니다. 파기 절차·시한의 세부 기준은 [대표 결정: 파기 절차]에서 정합니다.

7.3 이용자 PC의 `.padiem-backup` 사본은 이용자 PC에 남으며, 이용자가 직접 지울 수 있습니다.

## 8. 이용자의 권리

이용자는 자신의 개인정보에 대해 다음을 할 수 있습니다.

1. 열람·확인
2. 정정·수정
3. 삭제(대화 삭제, 프로젝트 삭제 기능)
4. 처리 정지(기능별 끄기·일시중지)

권리 행사 창구: [대표 결정: 행사 창구(메일 등)]. 행사 요청은 [대표 결정: 처리 기한] 안에 처리합니다.

## 9. 쿠키와 로컬 저장

9.1 서비스는 로그인 상태를 유지하기 위해 세션 쿠키를 사용합니다.

9.2 서비스는 광고 추적 쿠키를 사용하지 않습니다. 추적 도구의 사용 여부는 게시 전 점검 항목입니다(README의 "코드에서 확인 못 한 사실" 참조).

## 10. 개인정보의 안전성 확보

- BYOK 키는 암호화(AES-GCM)하여 봉인된 상태로 저장하며, 화면에는 끝 4자리만 표시합니다.
- 로그인 콜백의 1회용 인증 코드는 접속 기록에 남지 않도록 걸러 냅니다.
- 비밀번호 재설정 메일 발송 수단이 없을 때는 실패를 솔직히 알리고 가짜 "발송됨" 응답을 만들지 않습니다.
- 자체 서버 백업은 암호화되어 외부로 나가며, 복호화 키는 백업과 함께 두지 않습니다.

## 11. AI 생성 결과에 대한 고지

서비스가 제공하는 답변·문서·견적 등은 AI 모델이 생성한 결과입니다. 생성 결과는 이용자가 검토한 뒤 사용해야 하며, 전문가의 확인을 대체하지 않습니다.
