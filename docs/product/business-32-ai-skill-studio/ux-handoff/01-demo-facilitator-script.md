# 01 — Demo Facilitator Script (10–12분)

실제 제품 데모 진행 대본입니다. 이 데모는 **합성 업무를 보여주는 프론트엔드
시연**이며, 실제 AI 실행·구매·저장·조직 연결을 수행한다고 말하지 않습니다.

데모 환경: `reference/business-32-ai-skill-studio-ux/` 를 로컬로 서빙
(`python3 -m http.server 8000`). 검증된 exact head
`73ec4718d0835248ab20d56bc68f3956536112b4` 기준.

전체 예상 시간: 약 11분. 데스크톱 뷰포트(1440×1100) 권장.

---

## 0. 도입 — 제품 문제 (1분)

- **버튼**: 없음
- **영역**: 브라우저 타이틀/첫 화면 전환 전 안내
- **핵심 문장**: "한 번의 업무를, 보이는 순서대로, 증거와 검토를 거쳐,
  재사용 가능한 조직 기술로 보존하는 실습실입니다."
- **오해 방지**: "지금 보여드리는 것은 합성 데이터 기반 시연이며, 실제 구매나
  실제 조직 연결은 하지 않습니다."
- **예상 시간**: 60초
- **실패 복구**: 새로고침 후 `기본 업무` 시나리오 선택.

## 1. 합성 업무 선택 (30초)

- **버튼**: `업무 시작`
- **영역**: bench 화면의 task card
- **핵심 문장**: "Nori Works(합성)의 공급업체 견적 3건을 비교하는 합성 업무를
  선택합니다."
- **오해 방지**: "이 조직과 견적은 모두 가상입니다."
- **예상 시간**: 30초
- **실패 복구**: `업무 실습대로` 또는 시나리오 재선택.

## 2. 필수 입력 확인 (40초)

- **버튼**: `필수 입력자료 확인` → `확인으로 보완` (비교 기준 항목)
- **영역**: brief → inputs 패널
- **핵심 문장**: "비교 기준이 확인되기 전에는 실행이 시작되지 않습니다."
- **오해 방지**: "누락된 자료를 자동으로 추정하지 않습니다."
- **예상 시간**: 40초
- **실패 복구**: `입력자료 다시 확인`으로 목록 재확인.

## 3. 단계별 실행 시작 + AI 보조와 사람 행동 구분 (1분)

- **버튼**: `단계별 실행 시작` → `단계 완료` 반복
- **영역**: step-ledger, `AI-ASSISTED STEP` / `HUMAN ACTION` 라벨
- **핵심 문장**: "사람이 하는 일과 AI가 보조하는 일이 라벨로 구분됩니다."
- **오해 방지**: "AI가 사람의 결정을 대신하지 않습니다."
- **예상 시간**: 60초
- **실패 복구**: 중단 후 `재개`로 이어서 진행.

## 4. SOURCE EVIDENCE (40초)

- **버튼**: `증거 열기`
- **영역**: evidence drawer의 견적 3건과 비교 원장
- **핵심 문장**: "모든 비교는 출처 증거 위에서 이뤄집니다."
- **오해 방지**: "증거는 합성 견적서이며 실제 문서가 아닙니다."
- **예상 시간**: 40초
- **실패 복구**: `증거 패널 닫기`(또는 Escape) 후 다시 열기.

## 5. MISSING EVIDENCE (40초)

- **버튼**: `보완 요청 기록` → `재개` → `재개 확인`
- **영역**: MISSING EVIDENCE 플래그
- **핵심 문장**: "견적 B의 보증 조건이 없어 추천을 확정하지 않습니다."
- **오해 방지**: "누락을 채워 넣거나 최저가로 대신 판단하지 않습니다."
- **예상 시간**: 40초
- **실패 복구**: `실행 중단` → `재개`.

## 6. CONFLICTING EVIDENCE (1분)

- **버튼**: `견적 C 조건부 판단`
- **영역**: CONFLICTING EVIDENCE 비교 패널
- **핵심 문장**: "B가 총액은 낮지만 기준을 충족하지 못합니다. 최저가를 자동
  최선으로 판정하지 않습니다."
- **오해 방지**: "충돌은 사람이 판단합니다."
- **예상 시간**: 60초
- **실패 복구**: `실행 중단` 후 재개.

## 7. 중단·보완·재개 (30초)

- **버튼**: `실행 중단` → `재개` → `재개 확인`
- **영역**: STOPPED / RESUME 상태
- **핵심 문장**: "중단해도 진행 기록은 유지되고 같은 지점에서 재개됩니다."
- **예상 시간**: 30초
- **실패 복구**: `취소` 후 `업무 다시 선택`.

## 8. DRAFT RESULT (30초)

- **버튼**: `사람 검토 요청`
- **영역**: draft-paper의 초안과 DRAFT RESULT 라벨
- **핵심 문장**: "이 초안은 확정이 아니며 실제 구매 추천이 아닙니다."
- **예상 시간**: 30초
- **실패 복구**: `사람 검토 요청` 재시도.

## 9. 검토자 인계 (30초)

- **버튼**: `검토자에게 인계`
- **영역**: role banner (역할 · 합성 운영 책임자 · 사람 검토자)
- **핵심 문장**: "역할이 실행자에서 검토자로 인계됩니다."
- **오해 방지**: "실행자가 자신의 결과를 승인할 수 없습니다."
- **예상 시간**: 30초
- **실패 복구**: 잘못된 역할 전환은 validation-error로 안내.

## 10. 수정 요청 (30초)

- **버튼**: `수정 요청`
- **영역**: REVIEW CORRECTION / REJECTED STEP
- **핵심 문장**: "검토자가 근거가 부족한 추천을 수정 요청합니다."
- **예상 시간**: 30초
- **실패 복구**: `수정 사항 반영`으로 진행.

## 11. 실행자 반환 + 재실행 (1분)

- **버튼**: `실행자에게 반환` → `수정 사항 반영` → `수정된 절차 재실행` →
  단계 완료 반복
- **영역**: role banner 전환과 step-ledger 재실행
- **핵심 문장**: "수정된 절차를 다시 실행하고 다시 검토를 요청합니다."
- **예상 시간**: 60초
- **실패 복구**: `다시 검토 요청`.

## 12. 최종 승인 (30초)

- **버튼**: `검토 승인` → `사람 최종 승인`
- **영역**: NOT YET APPROVED → HUMAN-APPROVED
- **핵심 문장**: "승인은 사람 검토자만 할 수 있고, 승인 전에는 저장이
  차단됩니다."
- **예상 시간**: 30초
- **실패 복구**: 승인 전 저장 시도가 차단되는 화면을 먼저 보여주면 좋습니다.

## 13. 실행자 반환 + VERIFIED ORGANIZATIONAL AI SKILL 저장 (1분)

- **버튼**: `실행자에게 반환` → `스킬 카드 저장` → `버전·담당자·다음 검토일 확인`
- **영역**: 스킬 카드, RETAINED EXCEPTIONS, VERSION HISTORY
- **핵심 문장**: "미해결 예외까지 카드에 남습니다. 버전, 담당자, 다음 검토일이
  기록됩니다."
- **오해 방지**: "이 저장은 브라우저 메모리 시연이며 서버 저장이 아닙니다."
- **예상 시간**: 60초
- **실패 복구**: `새 업무 시작`으로 초기화 후 재시연.

- **오해 방지**: "아직 실제 고객, 실제 견적, 실제 저장, 실제 AI 실행은 없습니다."
