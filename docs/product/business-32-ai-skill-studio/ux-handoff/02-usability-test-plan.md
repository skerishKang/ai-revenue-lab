# 02 — Usability Test Plan

실제 참가자를 모집하지 않았습니다. 아래는 **가상 모집 기준과 계획**이며, 실제
사용성 검증이 완료되었다는 선언이 아닙니다. 본 계획은 파일럿 이후 승인된
usability 실행 단계에서 사용하도록 준비된 문서입니다.

## 목적

검증된 합성 UX의 15단계 journey가 실제 사용자에게 이해되는지, 역할·승인·
증거의 혼동이 없는지, 키보드/모바일에서 완료 가능한지 측정하기 위한 계획.

## 가상 참가자 모집 기준 (미실행)

| 역할 | 권장 수 | 자격 기준 | 제외 기준 |
| --- | --- | --- | --- |
| 업무 실행자 | 4 | 구매/견적 비교 업무 경험 또는 유사 사무 업무 | 해당 상품 개발 참여자 |
| 팀 검토자 | 3 | 결재/검토 경험, 이메일 기반 업무 승인 경험 | Business 32 구현 참여자 |
| 운영 관리자 | 2 | 조직 프로세스·교육 담당 | PR #354 리뷰어 |
| 정보보호·감사 관점 사용자 | 2 | 개인정보·감사 통제 관점 | 동일 세션 중복 |
| AI 초보 사용자 | 3 | 생성형 AI 사용 경험 0~3개월 | — |

참가자는 모두 합성 데이터 기반 시연에 동의해야 하며, 실데이터는 사용하지 않습니다.

## 테스트 과업

1. 업무 선택 — bench에서 합성 업무 선택
2. 필수자료 누락 해결 — input-incomplete 상태에서 비교 기준 보완
3. 증거 drawer 열기·닫기 — 열기/닫기/포커스 복귀
4. 충돌 근거 판단 — conflicting-evidence에서 사람 판단
5. 검토자 인계 — handoff-to-reviewer
6. 수정 요청 — reject-review 후 실행자 반환
7. 승인 후 저장 — human approval 후 operator 저장
8. 빈 업무대 복구 — empty-bench → load-tasks → initial
9. 오류 retry — fault 시나리오 → retry

## 측정 항목

| 항목 | 정의 | 가상 성과 기준 (가설) |
| --- | --- | --- |
| task completion | 과업 완료 여부 | 실행자 4/4, 검토자 3/3 |
| time on task | 과업별 소요 시간 | 15단계 전체 12분 이내 |
| misclick | 잘못된 action 클릭 수 | 과업당 0~1회 |
| role confusion | 역할 혼동 신호(잘못된 인계/승인 시도) | 전체 2회 이하 |
| approval confusion | 승인 권한 혼동 신호 | 전체 1회 이하 |
| evidence comprehension | 증거/누락/충돌 이해(사후 질문) | 참가자 70% 이상 |
| recovery success | 오류/취소 후 복구 성공 | 100% |
| keyboard completion | 키보드만으로 과업 완료 | 전체 80% 이상 |
| critical error | 치명적 오류(재시작 필요) | 0회 |

위 기준은 가설이며 파일럿 결과에 따라 조정합니다.

## 진행 규칙

- 실제 참가자 모집 전에 본 계획은 검토 승인이 필요합니다.
- 시연 중 진행자는 시나리오 버튼(`기본 업무`, `빈 업무대`, `오류 시뮬레이션`)을
  이용해 상태를 복구할 수 있습니다.
- 참가자 응답·오류는 이벤트 스펙(`06-analytics-event-spec.md`) 기준으로만 기록하며
  개인정보(이름·이메일·전화번호)를 수집하지 않습니다.

## 산출

파일럿 후 usability 실행 단계에서 측정 결과를 별도 문서로 기록합니다. 이 문서
자체는 usability 완료를 선언하지 않습니다.
