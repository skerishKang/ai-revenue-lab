- 상태: **OWNER 제품 방향 기록 / 향후 로드맵** — 구현·운영 지원 완료 아님
- 결정일: 2026-10-10 KST
- 제품 전략 오픈 이슈: [#4106](https://github.com/skerishKang/ai-revenue-lab/issues/4106)
- 제품 상위 이슈: [#3180](https://github.com/skerishKang/ai-revenue-lab/issues/3180)
- 현재 CGI: 기존 **Sol 6.1 단일 템플릿 정책 불변**, #3839 및 #4076 인수 작업 별도

## 1. 제품이 지향하는 고객 경험

고객이 기존 견적서를 올리는 이유는 매번 다른 견적서를 만들기 위해서가 아니라 **자신이 쓰던 견적서 양식을 그대로 쓰면서 작성 시간을 단축하기 위해서**다.

1. 최초에는 고객 원본의 표·수식·스타일·회사 로고·도장·인쇄 구성을 분석하고 **원본 파일 자체를 불변 보존**한다.
2. 원본 구조를 활용하여 변경 가능한 입력 필드와 계산 항목을 매핑한다. 사용자 승인 없이 고객 양식 전체를 임의 디자인으로 다시 그리지 않는다.
3. 기존 원본과 재현본을 비교하고 **인증된 내 견적서(Saved Quote Skill)**로 등록한다.
4. 이후 견적은 새 사실만 입력한다. QuoteCore에서 한 번 계산하고, 인증된 렌더러/형식별 어댑터로 **공유용 PDF와 편집 가능한 원본 계열 XLSX 또는 HWPX**를 출력한다.
5. 파일은 사용자에게 해당 형식이 **실제 구현·검증됐을 때만** 선택 가능하게 보여준다. 편집형 XLSX/HWPX를 모든 원본에 대해 이미 지원한다고 표기하지 않는다.

**핵심:** 최초 분석·인증에는 시간이 들 수 있지만 반복 견적 생성은 **원본 재분석 0회, PDF 출력 AI 호출 0회**로 빠르고 결정적이어야 한다.

## 2. 100% 동일의 의미를 분리한다

모든 사용자에게 픽셀 단위 100% 일치를 약속하지 않는다. 원본 양식을 중요시하는 사용자가 원하는 것은 **중요한 회사 서식이 유지되면서 금액과 내용이 정확한 견적서**다.

| 등급 축 | 반드시 확인할 사항 | 허용 정책 |
|---|---|---|
| **견적 내용/금액** | 품목, 순서, 수량, 단가, 공급가액, VAT, 총액, 거래처, 견적번호, 중요 특기사항 | **100% 정확해야 함**. 총액 계산 권위는 QuoteCore뿐 |
| **핵심 양식/브랜드** | 로고, 도장, 표 열/경계, 결제계좌, 회사정보, 인쇄 영역, 페이지 흐름, 누락·겹침 | 중요한 결함/요소 누락은 **허용 불가** |
| **비핵심 시각 차이** | 글꼴 폭, 미세한 간격·정렬·색 차이, 일부 공백·줄바꿈 | **고객·Owner가 차이를 명시적으로 확인하고 승인**한 경우에만 허용 |

인증 상태는 **CERTIFIED / CERTIFIED_WITH_TOLERANCE / REJECTED_OR_NEEDS_REVIEW**로 구분한다. CERTIFIED_WITH_TOLERANCE는 허용된 차이와 근거 이미지를 기록해야 한다. 렌더링 앱, 폰트, OS, 버전 및 PDF 출력 환경도 기록한다.

**원본 SHA-256 불변**은 원본 파일이 그대로 보존된다는 의미다. 새 견적 내용이 들어간 결과 파일까지 원본과 바이트 단위 동일해야 한다는 뜻은 아니다. 기존 Sol v1의 1~3품목 인증 바이트 보존과 같은 별도 불변 계약은 그대로 유지한다.

## 3. 원본별 처리는 다르게 한다

| 입력 | 원본 보존형 구현 방향 | 현재 등록 정책 / 출력 목표 |
|---|---|---|
| **XLSX** | 원본 OOXML의 셀, 병합, 행·열 치수, 테두리·스타일·숫자 표시, 수식, 이미지, 인쇄 영역/페이지 설정을 분석하고 승인된 셀·슬롯만 수정 | [#3586](https://github.com/skerishKang/ai-revenue-lab/issues/3586): 기존 **XLSX 소스 등록 사전검증 허용**. 인증된 신규 고객 템플릿에서 **XLSX+PDF** 목표. 실제 업로드/출력 전체 완료라고 간주 금지 |
| **HWPX** | 패키지 ZIP/XML의 표·셀·문단·스타일·그림·관계·용지 규칙을 유지한 채 지정 노드만 수정. 한컴에서 다시 열기/저장 및 PDF 비교 필요 | 현재 **미래 입력 형식**. 별도 승인/검증 후 **HWPX+PDF** 목표 |
| **구형 HWP** | 바이너리 자동 가공/변환 구현을 무리하게 늘리지 않음 | **등록 거부**. 사용자가 정당한 한컴 환경에서 HWPX로 저장한 신규 파일만 별도 검증 |
| **구형 XLS** | 구형 바이너리 Excel 자동 변환 없음 | **등록 거부**, 사용자가 XLSX로 정식 저장한 새 파일 검증 |
| **PDF** | 시각·텍스트·벡터·좌표·로고를 원본 재현 참조로 사용. 셀/수식과 같은 편집 구조가 원래 존재한다는 가정 금지 | 현재 PDF를 **자동 인증형 재사용 템플릿 입력으로 확대하지 않음**. 별도 승인된 분석·엔지니어링·인증 필요 |
| **이미지** | 이미지/OCR은 사실·시각 참조; 편집 가능한 표/수식/페이지 구조는 별도 생성·검증이 필요 | 현재 **자동 인증형 원본 등록 아님**. 단순 업로드만으로 동일한 XLSX/HWPX을 자동 생성한다고 보장 금지 |

**파일을 읽을 수 있음 ≠ 템플릿 등록 허용 ≠ 원본 편집형 출력 가능 ≠ 최종 PDF 인증.** 기존 PDF/이미지/DOCX 사실 추출 흐름을 새 템플릿 등록 정책과 혼동하지 않는다.

### XLSX에서 특별히 주의할 사항

원본의 병합 셀, 수식 결과/캐시, print area/scale, 이미지·도장·링크/관계 파일을 최대한 보존한다. 단 **Excel 수식이 QuoteCore와 다른 세금·총액을 만드는 것은 허용하지 않는다.** 원본 Excel Camera/연결그림, 외부 링크·매크로·복잡한 OLE/임베딩 등은 지원 여부를 개별 판정하고, 불명확하면 거부하거나 승인된 대체안을 제시한다. 위험한 외부 연결은 자동 실행하지 않는다.

### HWPX에서 특별히 주의할 사항

패키지 파싱 성공만으로 한컴오피스 출력 동일성을 주장하지 않는다. **원본 → 승인된 문단/셀 수정 → HWPX 저장 → 한컴 열기/편집 → PDF 렌더 비교**를 하나의 수용 흐름으로 검증한다. 폰트/그림/표 관계 누락, 다른 페이지 수, 줄바꿈·표 잘림은 명시적으로 기록하고 승인 또는 거부한다.

## 4. 신규 원본 등록과 반복 견적 생성은 다르다

**최초 1회**

- 원본 형식/크기/안전 검사 ([#3586](https://github.com/skerishKang/ai-revenue-lab/issues/3586)).
- 고객 비공개 원본의 SHA·소유자·권한 보존 ([#3884](https://github.com/skerishKang/ai-revenue-lab/issues/3884)).
- 원본 구조 분석 / 잠정 슬롯 매핑 ([#3542](https://github.com/skerishKang/ai-revenue-lab/issues/3542)).
- 패키지 보존형 후보·동일 샘플 데이터로 PDF/편집형 원본 비교.
- 중요 요소 개별 검사와 고객/Owner 오차 승인 ([#3595](https://github.com/skerishKang/ai-revenue-lab/issues/3595)).
- 템플릿/렌더러/원본 참조의 **버전 인증**.

**그 후 반복 사용**

- 승인된 고객 Saved Quote Skill + 새로운 견적 사실 → QuoteDraft.
- **QuoteCore 단독 계산** → 승인된 버전의 결정적 렌더러로 PDF.
- XLSX/HWPX 어댑터가 별도로 인증된 경우 **동일 QuoteDraft/QuoteCore를 편집 가능한 형식으로도 출력**.
- 일반적인 반복 견적에서 원본 재분석·AI 재디자인·별도 계산 엔진 사용 금지.

사용자가 Excel/한글에서 다운로드 파일을 임의 수정한 경우 파디엠의 기존 PDF 인증과 별개다. 수정본을 새 견적으로 가져올 때 다시 매핑·재계산·권한 검사해야 한다.

## 5. 편집형 파일이 없어도 PDF가 불완전해지는 구조 금지

- 고객 기본값: **승인된 PDF 견적서**.
- 추가 선택지: 해당 템플릿에서 실제 지원하는 경우에만 **Excel(.xlsx) / 한글(.hwpx)** 다운로드 표시.
- 편집형 출력과 PDF의 수신처·수량·금액·세금·비고는 일치해야 한다. 한쪽 파일이 다른 견적 데이터를 조용히 갖는 것은 실패다.
- 원본 오피스 형식과 렌더링 환경이 다르면 동일 PDF 픽셀을 보장할 수 없다. 인증된 출력 환경과 승인된 차이를 알려준다.
- Google Drive [#3871](https://github.com/skerishKang/ai-revenue-lab/issues/3871)의 현재 JSON+PDF 저장 계약은 유지한다. 추후 XLSX/HWPX 자동 저장은 별도의 명시적 동의·버전·권한 계약 이후에만 가능하다.
- 같은 양식의 표본: 1/2/3/4/8/25/100품목 중 의미 있는 경계와 **첫/중간/최종 페이지**를 검증하되, 불필요한 전체 CI 중복 실행을 요구하지 않는다.

## 6. 현재 김범신 대표 CGI는 예외 없이 Sol 6.1

이번 장기 로드맵은 현행 CGI 원본 템플릿 전용 **Owner 결정**을 대체하지 않는다.

- 현재 CGI 견적서 PDF의 **단일 권위는 기존 Sol 6.1 소스 유래 템플릿**이다.
- 1~3품목 기존 Sol 인증본 보존, 4+품목은 [#3839](https://github.com/skerishKang/ai-revenue-lab/issues/3839)의 **같은 Sol 구현 확장/재인증** 후 지원한다.
- HTML 인쇄, GLM 또는 임의 XLSX/HWPX 생성기를 현재 CGI PDF의 **대체 템플릿·fallback으로 사용 금지**.
- 향후 XLSX 다운로드를 제공하더라도 **Sol PDF를 대체하는 것이 아닌 부가 출력**이며 별도 검증/승인이 필요하다.
- 첫 고객 인수 [#4076](https://github.com/skerishKang/ai-revenue-lab/issues/4076)과 기존 Sol 4+ 시각·인증은 지금 과제. **이 장기 정책 때문에 MVP를 P0에서 추가 지연시키지 않는다.**

## 8. 향후 별도 인수 기준

- 원본 파일 SHA-256 불변, 고객/워크스페이스 격리, 버전/출처 증명.
- 등록 허용 형식 사전 검사와 지원 불가 객체 거부.
- 원본 편집 가능성: 인증된 XLSX/HWPX 파일을 **해당 오피스에서 실제 열기·수정·저장·재열기**.
- 원본 핵심 레이아웃·로고/도장·인쇄 결과와 승인 오차 기록.
- QuoteCore ↔ PDF ↔ 편집형 파일의 실제 **내용·금액 동일성**.
- 품목 개수 변화/다중 페이지/페이지 마지막 줄·결제 영역의 시각 인증.
- 고객별 Saved Quote Skill의 버전·권한·이력 일관성.
- 정상 반복 견적의 **원본 분석/렌더 AI 호출 0**, 실행 시간과 비용 실측.
- 출시할 파일 형식별 실제 E2E까지 검증. 개발 PR 병합만으로 기능 활성화 선언 금지.

**진행 순서:** 지금은 이 정책만 기록 → 실제 다른 고객의 승인된 XLSX 원본을 통해 구조 보존·PDF+XLSX 증명 → 별도 Owner 결정으로 HWPX 등록·편집·PDF 검증 → 실제 수요/측정에 따라 #3708 분석 인프라 검토. **이 정책과 달리 구현 우선순위를 변경하려면 Owner의 새 결정이 필요하다.**
