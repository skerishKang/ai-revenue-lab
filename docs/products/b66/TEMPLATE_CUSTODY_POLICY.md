## 1. 기본 판단

**현재 CGI 견적서의 출력 템플릿은 기존 Sol 6.1 구현 하나로 확정되었습니다.** 1~3개 품목을 넘어가는 행·페이지 확장과 필드의 추가·수정·삭제는 **Sol 템플릿 자체를 변경**합니다. GLM 비교물, 별도 HTML 인쇄 양식 또는 새 생성 모델 템플릿으로 대체하지 않습니다. 이 결정은 [B66 공식 원칙](README.md#owner-locked-cgi-rendering-decision--2026-10-09) 및 [#3839](https://github.com/skerishKang/ai-revenue-lab/issues/3839)에 따릅니다. 고객이 자기 양식을 맡기는 **향후 파일 보관·반환 기능**은 CGI 템플릿 교체나 자동 활성화를 승인한 것이 아닙니다.

**우리가 표준 양식을 보유하는 것과 고객이 업로드한 자기 양식을 보관·돌려받는 것은 별개입니다.**

- **공개 표준 양식**(소유자의 공개 허가를 받은 김범신 CGI 등): 버전 관리와 코드 검토가 가능한 **Git 저장소**. 원본 형태·렌더러·필드 배치·승인 범위를 변경 이력으로 보관합니다. 공개 샘플의 회사 정보가 공개 승인되었다고 **다른 고객의 정보까지 공개할 권한이 생기지 않습니다**.
- **고객 업로드 원본**: 고객 계정/워크스페이스에 속하는 **비공개 R2 파일 저장소(또는 승인된 기존 객체 저장소)**. 원본을 불변 바이트와 SHA-256으로 보관하고, 고객에게 인증된 내보내기/다운로드 경로로 그대로 돌려줍니다.
- **승인된 사용자 템플릿**: 같은 고객 영역에 버전별로 편집 가능한 구조·필드 매핑·렌더 리소스를 보관합니다. 원본 파일과 새 견적 출력물은 구분합니다.
- **견적 내용**: 거래처·공급자·품목·단가·수량·날짜 등 고객별 실데이터는 **공유 템플릿 밖**에 두며, 로그인 계정의 D1 견적 이력(#3405) 또는 별도 승인된 개인 정보 저장 구조를 사용합니다.

## 2. 권장 데이터 흐름

```text
최초 1회 업로드
고객 원본 XLSX/PDF (회원/워크스페이스 인증)
    │
    ├─ [R2 PRIVATE] immutable /template-source/<version>  ← 원본 해시
    │
    ├─ [D1] 소유자·파일 유형·SHA·버전·업로드 시각·R2 object key
    │
    └─ 템플릿 분석 → Canonical Template 후보 → 재현 → 인증 (#3595)
          ├─ [R2 PRIVATE] /compiled-template/<version> (실행 아티팩트)
          └─ [D1] Approved Saved Quote Skill / 배정 상태

반복 견적
선택된 승인 템플릿(공개 표준 or 내 R2 개인 템플릿)
 + 고객별 회사 정보 + 거래처 + 품목 + 수량 + 단가 + 날짜
 → QuoteCore 재계산
 → 인증된 결정적 렌더러 (모델 추가 호출 없이)
 → 미리보기 / PDF / D1 견적 이력
 → 고객 요청 시 원본/승인 템플릿/결과물 내보내기

선택 기능: [내 Google Drive에 저장·열기] (#3871)
```

기존 표준 양식은 공용 구조가 바뀌지 않으면 재컴파일하지 않습니다. 고객별 **숫자만**이 아니라 업체명, 수신처, 품목, 날짜, 지급 조건 등 **허용된 가변 슬롯 전체**를 바꿀 수 있습니다. 허용 범위 밖 디자인 변경은 새 버전/인증 대상으로 취급합니다.

## 3. 암호화·권한 규칙

- Cloudflare [D1 데이터 보안](https://developers.cloudflare.com/d1/reference/data-security/)과 [R2 데이터 보안](https://developers.cloudflare.com/r2/reference/data-security/)에 따라 **저장 중 AES-256 암호화 및 통신 중 TLS**를 기본 사용합니다. 이는 클라우드 서비스 관리형 암호화이며 **앱 개발자가 파일마다 암호화했다는 주장과 다릅니다**.
- 가장 중요한 실제 고객 보호는 **서버에서 검증한 인증 사용자/워크스페이스에 따른 접근 제한**입니다. 클라이언트가 임의로 전달한 소유자 ID나 R2 key를 그대로 신뢰하지 않습니다.
- 민감 회사 정보(계좌, 비공개 도장, 연락처 등)에 추가 **앱 수준 암호화**가 필요하다면 위협 모델·검색 요구·키 회전·복구·파기 정책을 먼저 정하고 인증 암호화(예: AES-GCM)와 외부 비밀/키 관리를 구현합니다. **키를 Git·템플릿 JSON·브라우저 로컬 저장소에 넣지 않습니다.**
- 암호화했어도 보존 원본을 GitHub 공개 저장소에 올리지 않습니다. Base64 변환은 암호화가 아닙니다.
- 원본 보관은 **고객의 명시적 보관 동의 및 보관 기간 고지**를 기본으로 합니다. 삭제, 계정 종료, 백업/복원, 감사 로그, 업로드 한도, 악성 문서 검사, 보관 요금은 실제 기능 활성화 전에 별도로 검증합니다.

## 5. 실제 고객 반환 요구사항 (#3884)

1. 고객이 기존 양식을 한 번 올리면 **원본 그대로 비공개 보관**(원본 SHA-256, 크기, 소유자, 버전).
2. 다른 브라우저·휴대전화에서 같은 계정으로 로그인하면 **내 원본 내려받기**, **내 승인 템플릿 내보내기**, **최근 견적 복사·수정·PDF 다운로드**가 가능해야 합니다.
3. 다른 계정/워크스페이스는 목록·조회·다운로드 모두 접근할 수 없어야 하며 리소스 존재 여부도 노출하지 않습니다.
4. 복원·다운로드한 원본이 최초 업로드와 **해시가 일치**해야 합니다. 미리보기·PDF는 계산 권위가 아니라 QuoteCore 재계산 및 인증된 렌더 결과입니다.
5. 원본과 인증 템플릿/고객 PDF를 각각 삭제/유지하도록 정책을 구분합니다. 데이터가 남는데 삭제됐다고 표시하거나, 공유 링크만으로 무기한 접근을 허용하면 안 됩니다.
